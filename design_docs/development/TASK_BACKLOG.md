## Scope and task handoff

- The approved specs and decision log control behavior. Each feature has one backlog owner for traceability. Acceptance can require multiple cards. Shared features such as UI-003, CHAR-023, DEV-014 and CORE-012 require real consumer integration at the appropriate milestone.
- A task's prerequisites describe proposed delivery order. Record producer and consumer interfaces, exact fixture and expected outcomes before dispatch. Use the limited slice only where the parent specifications and milestone allow it. Carry deferred integration assertions forward until the real consumers pass.
- A Medium card is sized around one focused change and verification path. Large cards require scope review before assignment. Split at a separately testable boundary when the full card needs unrelated production changes or too many simultaneous owner contracts. Status changes require linked evidence and explicit implementation authorization.
- Approved features retain any internal conditional, deferred or unsupported capability limits. For example, feasibility conditions for launch tooling and mod execution remain visible through their linked specs. Review those clauses before opening implementation scope.
