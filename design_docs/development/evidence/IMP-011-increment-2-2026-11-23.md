## Delivered implementation

- `binding_configuration.gd` owns the application-wide stable action inventory,
  two keyboard/mouse and two controller slots, private drafts, detached projections,
  whole-candidate validation, explicit conflict Replace/Cancel, clear, reset and
  complete effective publication. Slide is explicitly unbound in stock defaults.
  Context overlap is declared: gameplay actions overlap; UI Confirm/Back overlap
  only each other. Plain/chord precedence is intentional; ambiguous simultaneous
  chords are rejected. Resets cannot silently displace custom assignments.
- `binding_editor.gd` implements the stock Controls screen and capture handlers.
  Physical keys use current-layout labels and explicit left/right modifier sides.
  Mouse buttons/wheel, one modifier plus key/mouse, controller buttons and trigger
  capture are supported. Unsupported inputs report reasons. Trigger thresholds
  remain 0.55/0.45. Opening held inputs must release before assignment; reserved
  Escape/Start and effective controller Back recover even during that wait. Escape,
  Back and focus loss cancel without clearing. Motion/drift cannot become a slot.
- Analog pair selection, independent deadzones and Y inversion use separate
  validated edits. DFU pair labels translate to Godot's left/right stick pairs.
  Approved response/mode defaults are retained; editing them is rejected until
  their camera/gait/posture consumers exist. No later consumer was invented.
- `StartupController` composes the controls owner with `StartupSettingsOwner`.
  Application acceptance, effective runtime controls and persisted values remain
  distinct. Failed disk publication keeps the applied controls in memory, shows
  UNSAVED and permits retry. Recreated input consumers receive effective controls.
  Explicit empty slots survive restart; missing new actions get conflict-free
  defaults or remain unbound with an identifying notice.
- CORE settings extensions perform compatible action/analog/response group repair
  and unsupported owner-format guarding through the existing recovery flow.
  Unrelated valid assignments and unknown entries are preserved. No new storage
  format, root, library or dependency was introduced.
- Stock title and Pause settings entry, controller UI Confirm/Back, pre-GUI capture,
  consumed wheel completion and disposal are wired through normal interfaces.
  Publication cancels unfinished input through the accepted epoch interface and
  quarantines held physical inputs without synthetic releases or new starts.
  The 256-edge queue, overflow policy, aggregation and independent CORE holds remain.

Contracts are in `main_project/scripts/input/README.md`,
`scripts/startup/README.md` and `scripts/session/README.md`. The task, backlog,
readiness, milestone and maintained verification documentation are synchronized.
Defaults retain the previously approved INPUT_DEFAULTS/DFU baseline; no reference,
classic/base data or DFU source was modified. New implementation is GDScript and
uses the existing native adapters without toolchain or licensing changes.
