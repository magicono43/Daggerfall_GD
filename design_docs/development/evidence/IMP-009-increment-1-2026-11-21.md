## Implemented scope and contracts

documents fields, offsets, bounds, source inventory, stable mappings, operations,
provenance and readiness. Delivered GDScript readers support checked flats,
74-byte class/monster careers, uninterpreted 40-byte painting metadata,
NUL-delimited BIO.DAT narrative strings, and a separately identified BIOG text
question/answer/effect transport. All use explicit typed fields and detached views.

The single `actor.inputs:catalog` schema reuses the existing definition registry
and real MOD/CORE pre-menu transaction. Shipped, folder, ZIP and loose contributions
retain deterministic add/replace/patch, original identity, separate contributors/
field winners, whole-contribution rejection, explicit omission, mandatory-reference
validation, stale tickets, menu failure/retry and run-long locks. Required classic
sources register before preparation. The shipped authored format profile is loaded
through FileAccess from the exported PCK, not an absolute-filesystem reader.

Actors and appearances use separate explicit references. Added IDs are not bounded
by legacy flat packing. Duplicate/ambiguous/canonical-alias mappings reject.
Biography set, question and answer identities derive from explicit source markers,
not translated text or transient array position. Effects preserve checked command,
type, target and required parameters; they never execute. Unknown unused career/
flat bytes and explicitly marked unused author metadata remain uninterpreted.

Structural lookup reports `semantic_ready:false`. Every gameplay-use request fails
with `semantic_unavailable`, definition and provider context. No fixture validator
can certify production semantics, and the readers import no live RNG/actor/item
allocator or gameplay-owner API. Repeated reads/reference validation leave CORE
session and published definitions unchanged.
