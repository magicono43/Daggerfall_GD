## Delivered behavior and concrete handoff

| Owner/interface | Implementation and observable result |
| --- | --- |
| Normal startup | `main_project/project.godot` opens `scenes/startup.tscn`; `startup_shell.gd` renders without original assets. No arbitrary-key trigger or automatic character entry. |
| Root selection | `StartupStorageOwner.resolve(launch, fallback)` captures executable/per-user directories and marker choice once. Checked results distinguish I/O failure and root-in-use, with path/operation and applicable recovery choices. A context projects one root to saves/settings/mod data/logs/cache. The owner and consumers retain the same `StartupStorageAdapter` and its native lease. |
| Development isolation | Editor runs default to the provisional `Daggerfall GD Development` LocalAppData directory; explicit `--use-player-storage` selects player launch inputs and still needs the lease. Normal storage's provisional name is `Daggerfall GD`; final game naming remains deferred. Fixtures use executable/user directories under `tests/.runs/`, independent of both. |
| Windows boundary | C++ `WindowsStorageLease` uses Windows per-user discovery, exclusive open-file handles, filesystem-resolved identity and flushed same-volume replacement. Required categories pass directory creation and temporary write/read/removal before consumers start. Optional logging/cache failure does not change the root. |
| Settings | `StartupSettingsOwner.initialize(reset)` validates packaged defaults, format 1 and owner-declared values/groups, retains unknown defined INI entries, adds missing defaults quietly, and reports initialization/load/recovery/incompatibility/installation/publication failure separately. Unsupported integer formats require explicit preserved reset; missing/malformed format metadata is damaged input. |
| Publication | Active `settings.ini`, one `.backup` validated revision and one separate `.recovery` damaged input. `.staged` output is reopened/validated before replacement; preservation/backup failures stop publication. Identical saves and parsing do not advance history. Restoring a backup preserves that backup; defaults recovery establishes a valid default backup. Startup failure blocks content/menu entry. |
| Preferences | `declare`, `declare_group`, `apply`, `save_accepted`, `pending` separate accepted, persisted and effective values. Known startup settings are classic path (restart) and Show setup (next launch, default false). Controlled owners exercise range/group validation, live rejection and live-versus-deferred grouping. Invalid/unclassified/late declarations block initialization rather than guessing timing. A live consumer's rejection contract retains/restores the previous working group; persistence retry does not reapply or activate pending values. |
| Logging | One `StartupLaunchLogger`, also the Godot engine diagnostic sink, rotates `Player.log` to `Player-prev.log` only once per launch. UTF-8, UTC timestamps, severities, exception traces, message flushes, pending/established public mod metadata, home-prefix filtering, no debug by default, repeated entries retained. Encoded output reserves a timestamped final notice within the 200 MiB cap; failures/cap disable file output and warn independently of the logger. Default engine file logging is disabled. |
| Setup routing | `StartupController` uses `check_classic`, `publish_packages`, `open_menu` checked providers. Classic rejection prevents package preparation; package rejection retains source/reason and publishes no invalid configuration. Main-menu readiness follows required publication and successful menu creation. Menu failure has Retry/Setup/Quit recovery; concurrent/repeated Continue is guarded. |
| Source configuration | Folder cancellation leaves the selection unchanged. Validated initial source is saved before activation; portable internal paths are executable-relative, external ones absolute. Menu source changes are accepted/persisted pending restart while the active source is retained. Accepted unsaved preferences remain retryable. |
| Real-provider absence | `provider_boundary.gd` reports unavailable content support. It cannot mistake a directory's existence for DATA validation or report real package publication. `controlled_startup_provider.gd` supplies explicit fixture outcomes only. |

INI is the UTF-8 Godot ConfigFile dialect, not a new external library. Unknown
defined entries are not applied; comments/whitespace are not retained. ConfigFile's
`null` denotes an omitted entry. There is no historical format migration to invent
for initial version 1. Session/location activation and display testing require their
actual owner contracts later; the startup declaration interface deliberately accepts
only implemented timing categories.

### Failures encountered and verification limits

The first C ABI method-registration attempt crashed Godot and displayed a Windows
memory-read dialog. Null native property-description fields were corrected before
acceptance testing. Subsequent imports, both suites, process scenarios and debug/
release exports passed without that crash. Initial script parse/type errors and an
export fixture-root resolution error were fixed and rerun; failed exploratory runs
remain in ignored local evidence and are not counted as passes.

Synthetic damaged INIs intentionally emit ConfigFile parser errors, and the logger
test intentionally emits a warning. Input contents are omitted from game file-log
parser diagnostics. The sandboxed engine also reports inability to read the Windows
root-certificate store before startup; this task performs no network operation.

The cap algorithm uses a reduced fixture budget plus an assertion of the exact
209,715,200-byte production constant; no 200 MiB full-file endurance run was counted.
Native replacement flushes individual staged files; cross-file publication is not
an atomic transaction. Physical power cuts, drive disconnection, full-disk hardware
behavior, network-share filesystems and non-Windows platforms were not tested.
Process-kill results do not promise universal power-loss survival. Rendered checks
use controlled mouse input and agent visual inspection, not a human playtest or
an actual ACL change on a player profile.
