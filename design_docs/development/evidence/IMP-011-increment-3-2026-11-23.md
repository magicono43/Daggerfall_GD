## Implemented scope

The normal startup/session path composes `view_cursor.gd` and a current Camera3D.
Mouse motion reaches the view only after engine GUI refusal; discrete Center and
Cursor Toggle use accepted rebindable edges. Mouse displacement accumulates once,
with mouse → held keyboard → selected stick priority and zero-net/opposing-key
suppression. Rates and exponential smoothing use eligible presentation seconds;
mouse displacement is never multiplied by elapsed time as a velocity. Actual
resolved yaw/pitch drive both camera and checked detached center/cursor rays.

Pitch is ±89°, repeated yaw unrestricted, roll zero, Center immediate. Menus,
focus, capture/configuration, placement, session replacement, cursor entry/exit
and gesture ownership clear pending response. A handoff fence suppresses queued
warp/recapture motion until the first eligible presentation update. Cursor entry
centers; gameplay cursor selection survives ordinary menus; native restore chooses
captured look only under existing readiness/context gates. Cursor mode alone
neither pauses simulation nor disables movement intent. Stock GUI widgets consume
their clicks before gameplay. The old competing SessionShell mouse-mode assignment
is removed.

Checked requester/session gesture reservations stop pending response without
locking normal attacks or synthesizing deliberate releases. Matching tokens alone
release reservations; context changes cancel them. Native facing capture/restore
is delivered as an owner interface, with no cursor/tail/token save state. Actual
SAVE, locomotion, activation, COMBAT, cosmetic AV and physical controller/IME
integrations remain open. The rendered geometry/provider is controlled test content.

The actual stock editor stages independent axes, inversion, smoothing enable/time,
keyboard rate and cursor speed through application controls. Input/view prevalidate
and publish coherently. Application outcome is checked separately from disk state:
failed staging retains effective response and reports UNSAVED/Retry; retry persists
it; Cancel preserves accepted values; recreated views receive effective values.
Compatible version-1 smoothing additions preserve supported response values,
explicitly unbound slots and unknown entries. Gait/posture defaults remain retained
without inactive edits being reported as applied.

The [view contract](../../../main_project/scripts/input/VIEW_CURSOR.md) records
units, bounds, smoothing formula and handoff/provider interfaces. No DFU source
code/data was copied for this increment: behavior comes from approved MOVE-003,
INPUT_DEFAULTS, CORE-003/006/016 and GAD-03/11; the response algorithm and numeric
validation ranges are documented engineering choices within that authority.
