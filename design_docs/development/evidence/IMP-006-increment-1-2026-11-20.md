## Delivered numeric contracts

The concrete API, supported domains and ownership limits are in
[the RULE README](../../../main_project/scripts/rule/README.md).

- `pcg32-xsh-rr-v1`: local sources, explicit unsigned-64 seed limbs, exact reference
  two-step initialization, 64-bit wrapping, 32-bit truncation/rotation. Four 16-bit
  limbs emulate unsigned operations; multiplication columns cannot overflow signed
  64-bit arithmetic. Actual Godot engine vectors cover high-bit/all-ones seeds.
- Raw unsigned-32 output and unbiased rejection mapping for integer bounds
  1..4294967295. Invalid requests consume nothing; bound 1 consumes one raw draw;
  internal rejection advances raw count while completing one logical bounded draw.
- `rpg-rng-v1`: exactly 32 bytes; SHA-256 of domain/zero/material/zero/lowercase
  purpose; little-endian initstate/initseq and high-bit clearing. Combat,
  progression, loot and quest derive independently with zero gameplay draws.
  Explicit fixture material is supported. Normal material uses `OS.get_entropy(32)`
  and validates the returned length; no clock/fixed/global fallback is present.
  Missing/short/long/wrong-type material fails. OS-level service failure was not
  forced; empty/short responses exercise the same explicit failure validator.
- `dfu-dfrandom-v1`: explicit unsigned-32 seed including zero, local operation state,
  raw 0..32767, one draw for each valid remainder-mapped range. Signed-32 endpoints
  and positive signed-32 widths reject unsupported/reversed/empty/overflowing ranges
  before drawing. Inclusive singletons consume once. Low-32 recurrence is proven
  sufficient for every observable bits-16..30 result. No global saved seed slot.
- RULE-001 integer computed chances saturate with safe comparisons. Inclusive roll
  1..100 uses the supplied checked source. Even 0/100 consume one logical draw;
  success and failure are complementary fields of the same result. Invalid source,
  fractional chance and out-of-contract raw/bounded results fail explicitly.

No session admission/load initialization, retained-result store, formula registry,
executable provider activation, native save schema, gameplay formula, rule
interpreter or player-facing dice display was added.
