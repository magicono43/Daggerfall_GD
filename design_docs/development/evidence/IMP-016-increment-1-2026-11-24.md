## Implemented engineering scope

The normal single CORE composes the real CHAR owner, bound to application DATA
and RULE. It owns isolated permanent attributes/skills, retained creation choices,
ranked S0/progression facts, positive stored base health and current pools. It owns
no physical pose/shape; accepted LOC/MOVE authority remains unchanged. Detached
per-actor projections expose permanent/raw/live/caps, exact source breakdowns,
formula provenance, limits/units and explicit pending conditions.

The [owner contract](../../../main_project/scripts/char/README.md) documents
`actor-state-v1`, strict runtime numeric domains, validated supported permanent
bounds, added skills without extra attributes, scoped atomic source batches,
required-source revision/fingerprint receipts and quiescent reconstruction.
Bindings are trusted owner interfaces, not a universal equipment/effect stacker.
Reconciliation preserves hidden/opposing contributions and base health. Maximum
increases never refill; decreases clamp only amounts above the new maximum.

Fresh construction accepts explicit complete captured level-1 inputs and an
initialized clock. Initial health is 25 + published career HP; permanent initial
skills precede ranked S0 (all Primary/top two Major/top Minor), practice is zero,
advancement/activity baselines preserve the supplied game-millisecond clock and
paid training is explicitly never trained. No biography, grants, creation rolls,
advancement, reward allocation or higher-level initialization is fabricated.
Breath remains explicitly activity-owner-pending rather than generically filled.

The [RULE contract](../../../main_project/scripts/rule/FORMULA_DISPATCH.md) adds
eight declared actor hooks to the existing registry. Seven approved baseline
helpers plus deterministic initial health use bounded exact rational input and
mathematical floor. The fixture integer signature is incompatible. Normal MOD
selection, actual menu lock, owner admission, monitored callback failure and
no-fallback recovery remain authoritative. CORE admits only its composed CHAR
under the original safe baseline/initialization ticket before ready; ready-session
consumers retain ordinary explicit hook bindings. No RNG capability is granted.

The small `actor.baseline` DATA policy supports bounds/caps/skills and exact career
ratios through shipped → checked MOD → captured loose publication. The fixture
independently checks all three provenance tiers. Structural actor readiness stays
false. CHAR qualifies only playable class HP/multiplier/mapped progression-group
inputs; it rejects City Watch/source-only and enemy careers. FLATS ambiguity and
guarded BIOG correction remain unchanged. Classic/reference/base inputs are
read-only. [Provenance](../../../main_project/content/actors/PROVENANCE.md) records
DFU source choices, MIT notice, explicit default multiplier cases and intentional
non-parity boundaries. No new dependency/toolchain/native adapter was introduced.

Only supported quiescent owner records reconstruct. Base health, current pools,
zero-versus-missing S0, practice, timestamps, training state, retained outcomes and
opaque pending obligations survive; sources must match saved receipts. Unsupported
policy/incomplete/invalid state fails. There is no refill, reroll, health-gain
replay or consequence dispatch. In-memory reconstruction is not native SAVE.
