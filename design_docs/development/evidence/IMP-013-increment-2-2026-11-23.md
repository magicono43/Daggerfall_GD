## Delivered scope

The normal session shell still composes one `location_assembly.gd` extending the
accepted dungeon owner. Optional validated DATA doorway declarations build a
preparation-private index, published atomically with geometry under the original
CORE ticket. There is no parallel registry or physical-pose owner. The detailed
[owner/data contract](../../../main_project/scripts/loc/LOCATION_DOORWAYS.md)
records the complete replaceable schema, transforms, guards, side checks and
readiness semantics.

Each link retains independent exterior entrance, interior instance, local exit
and marker identities. Shared entrances name the same building-scoped instance;
independent instances can reuse a template. Template/provenance and live scene
handles remain separate facts. Each supported interior static exit requires its
own exterior binding. Entry through front never rewrites back's destination.

Preparation checks original model planes, effective block/record/parent guards,
source model hashes, original marker roles, inward landing side and perpendicular
projection onto the actual aperture. Authored unit facing remains literal and
independent of the side check. Exact coincident-region selectors and complete
MOD/loose overrides use existing DATA precedence. Missing, incompatible or
ambiguous required links fail with referring/target identities and reason,
discarding staging and retaining the valid exterior/context. Changed doorway
meaning remains behind the existing structural variant compatibility gate.

The real IMP-061 scoped marker consumer boundary is reused for RMB handoffs.
It carries selected identities, desired anchor/facing and intended space/side,
content/layout/binding versions, original ticket and separate activation epoch.
Inspection cannot become arrival, named arrival cannot be retargeted, and stale
content/layout/activation/retirement or late provider receipts reject. Controlled
pending access/placement callbacks and one rejection-only variant proposal test
these boundaries; they do not qualify real MOVE, access or gameplay readiness.

Additional maintained boundaries reject finite anchors outside the qualified
8192 m local frame and keep per-door binding readiness tied to the active
instance, including inspection aliases. Template identity includes both the
block and building. A real disposable MOD patch replaces another shipped RMB
with authored data while retaining its genuine immutable receipt: classic-only
guards reject that authored interpretation, and explicit authored guards pass.
That fixture replacement is not a new shipped baseline or a source-file edit.

### Preparation and query cost

real classic catalogs/media. Headless/rendered intake measured **12.206/12.260 s**,
preparation **15.456/15.111 s**, and detached startup projection **777.194/664.099 ms**.
These include the complete fixture composition; they are observations, not budgets.

A matched before/after case uses the same 64 native occurrences, **128 actual
model instances, 128 Jolt bodies and 48,512 triangles**. Unbound preparation took
**1.134/1.146 s** headless/rendered; adding **128 independent bindings** took
**1.339/1.330 s**. Binding preparation itself measured **136.642/137.065 ms**.
Both decode one block once. The bound case decodes two unique model resources
instead of one, because it also qualifies the counterpart interior topology;
it does not claim counterpart live collision readiness.

the prepared index and detached selected record only, with no catalog copy,
block decoding or graph construction. The retained 64-classic-block regression
also assembles **576 real models /128 bodies /83,648 triangles** in
**1.542/1.549 s**, with **51.354/44.239 ms** for 1000 scoped binding queries.
Godot's observed static-allocation peaks were **2,764,768,501/2,787,785,646 bytes**
for that full-composition fixture; these are not RSS or an invented memory budget.
