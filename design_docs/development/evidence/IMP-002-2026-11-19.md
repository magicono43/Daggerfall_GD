## Delivered implementation and interfaces

All paths below are relative to `main_project/`.

| Owner | Concrete interface and behavior |
| --- | --- |
| Application composition | `scripts/startup/startup_shell.gd` creates `session/session_shell.gd` in the existing startup scene. Main-menu rendering delegates to it only after the existing startup controller reaches main-menu readiness. Session requests from the shell cannot bypass the required startup route. The stock entry provider rejects unavailable character/restore support explicitly. |
| CORE operations | `SessionLifecycle.request({id, mode, origin, selection})` captures deep value data, rejects runtime objects, changed reuse of an identity, stale origins and conflicts. Supported routing modes are new, load, voluntary return, authority-confirmed death return and shutdown. Routing is not implementation of their later gameplay providers. Same-identity redelivery observes a retained result and never repeats work. |
| Provider handoff | `session_provider.gd` declares checked `prepare`, `initialize_baseline`, `initialize`, `cleanup`, `death_presentation` and `open_menu`, plus preparation cancellation. Immediate results or `{pending: true}` are supported. CORE's corresponding `complete_*` methods require the exact issued operation/generation/scope ticket and expected phase. Cleanup has its own attempt generation and outstanding-result flag. Failed-attempt late success cannot release the cleanup block. |
| Replacement | Cancellable preflight preserves the outgoing session and holds simulation/input. Living-session discard consent follows successful preflight. Replacement stops gameplay, retires UI scope, invokes owner cleanup and waits before baseline initialization. Baseline readiness is a separate checked milestone before provider placement/restore/readiness. Duplicate baseline completion cannot reset restored state. Initialization failure cleans the incomplete scope; unsafe cleanup produces one failed terminal result but independently blocks admission until safe Retry Cleanup. |
| Bindings | Mode owners declare role, owner, session/location lifetime, requiredness, initialized provider, dependencies and an approved optional fallback. Missing inventory, absent/duplicate required providers and missing declared dependencies reject readiness. Supported optional degradation diagnoses disabled capability. There is no scene-name search, service creation on access, invented player/world baseline or domain reset through observer order. Providers remain responsible for their inventory, dependency-safe owner initialization, work cancellation, subscription disconnection and idempotent actual disposal. |
| Lifecycle publication | `snapshot()` is a read-only committed projection with application, session/status, baseline/readiness, operation/phase and version dimensions. State-change publication precedes its milestone. Reentrant confirmations, cancellations and completions defer to the notification boundary and revalidate. Admission during notification reports busy. Baseline, new-session, restored, confirmed-death, safely-ended and usable-menu milestones remain distinct. Scoped subscriptions are explicitly disconnected at disposal. |
| CORE gates | `SessionGates.acquire(owner, scope, channels)` issues distinct tokens; `release(token, owner)` cannot release another requester. Session retirement removes only that scope. Simulation, gameplay input, independent presentation and HUD hides are separate channels; app focus/shutdown holds survive session retirement. Ready/safe state remains necessary for gameplay. HUD preference/binding and hide reasons are independent of pause. Current-session required-service loss gates recovery. |
| UI navigation | `SessionWindowStack.open/close/replace/return_to_game/respond/complete_response` use stable layer and context identities. Covered layers retain drafts/focus and independent holds. Delayed close cannot pop the next layer. Required decisions block Back/Return to Game. Pending responses reject duplicates. Preparation failure retains the previous view. Replacement retains its hold without a resumed frame. Retirement removes session windows and invalidates pending responses. |
| Input/context | `capture` retains deliberate press edges across a brief tap, suppresses echoes/held repeats and expires handoff input. `dispatch` implements the declared shortcut priority, removes both simultaneous quick actions before ranking, and submits at most one winner without fallback. Modals block gameplay fallthrough even with no ordinary UI pause. Only Escape/options is wired to stock keyboard input here; real gameplay bindings, cursor capture and owner delivery remain IMP-011. The shell retains visible cursor for its menu controls. |
| Stock controls | Title, gameplay destination, Pause, nested Settings, discard choice and independent operation/error/shutdown screens use the existing responsive scroll container. Initial safe focus and eligible prior focus are restored without activation. Render-generation checks invalidate old button callbacks. Pause exposes Resume, disabled Save/Load with reasons, Settings, Return to Title/Setup and Quit. Available startup preferences use the existing settings owner; dirty settings support Apply/Discard/Keep Editing. Unavailable audio controls are explained rather than inventing settings. |
| Prompts | `session_prompt.gd` provides stock information/choice/single-line text presentation through `show_prompt` and the same window response interface. Responses have stable IDs; consequential choices can specify safe focus or remain unarmed. Rejected text preserves the prompt/draft/reason; accepted responses close once. Back reports permitted cancellation to the owner. Godot LineEdit owns actual text/IME composition; a composition guard prevents its ending Enter from also submitting. Pending owner resolution and scope retirement retain identity checks. |
| Return and death | Voluntary return requires consent; an already-menu return is unchanged. Confirmed death requires the bound current-session authority, not an animation callback. Session-ended follows safe cleanup. Death presentation is independently scoped and usable menu readiness waits for completion/skip/failure bypass. A failed menu retry does not rerun cleanup or completed presentation. Stock missing playback uses the approved silent bypass. No original video decoder is claimed. |
| Quit/setup | UI Quit and interceptable OS-close share one deduplicated intent and requester hold. Conflicting session work reaches completion or is canceled through preflight rules. Consent is checked against the current session. Pending shutdown blocks new conflicting admissions; cancel releases only its hold. After teardown, accepted application preferences are saved through the existing owner. Publication failure retains committed files and offers Retry or explicit Quit Without Saving Preferences. Logging and storage remain live for this work and close in the existing application exit callback. Setup return uses confirmed session return and retains the configured source. |
| Cadence contract | `session_cadence.gd` has no production frequency/default or automatic gameplay consumer. A session owner must explicitly supply interval, positive consumer-work budget and dependency-ordered checked consumers. Eligible deltas alone accumulate. Fraction/backlog and interrupted consumer position are retained, work is bounded, completed consumers do not repeat, failure gates recovery and retirement clears callbacks/time. Fixture-only values are 0.1 seconds and a budget of two consumer deliveries per call. Native timing restoration, actual order/RNG opportunities and overload policy remain deferred owner work. |

The GDScript owner API is a trusted in-process boundary, not a security sandbox.
CORE alone writes lifecycle readiness/safety/session fields. Other consumers query
projections and request/release their own holds. Future mode providers use the
same interfaces; controlled providers are under `tests/` and are selected only by
the isolated fixture, never as a fallback for ordinary startup.
