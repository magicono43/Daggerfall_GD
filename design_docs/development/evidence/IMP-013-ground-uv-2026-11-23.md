# IMP-013 — ground image orientation follow-up

The user reviewed the increment-1 images and questioned the exterior road texture
placement. Investigation confirmed a LOC ground UV bug. This follow-up stays
within increment 1; it records no user acceptance or later-increment authorization.

## Cause and correction

The source tile grid, tile record/flag decoding and physical positions were
correct. Individual tile imagery was vertically reversed. DFU
`API/BaseImageFile.cs:GetColor32` writes decoded image rows bottom-up before Unity
upload. The project DATA image provider explicitly retains top-left-first rows.
The LOC ground mesh applied DFU's tile transformations without compensating for
that image-row convention.

The correction inverts the final sampled V coordinate after the rotation/flip
transform. It changes ground imagery only; source bytes, placement identities,
model/marker poses and ground/collision vertices remain intact. The explicit
`rmb-ground-top-left-uv-v1` interpretation is retained in ground provenance and
exterior geometry versions. The shared coordinate frame remains unchanged.

Read-only evidence is DFU's `GetColor32`, `ImageProcessing.RotateColors/FlipColors`,
`MeshReader.GetSimpleGroundPlaneMesh`, and the four matrices/translations in
`DaggerfallTilemapTextureArray.shader`. Existing DFU MIT licensing applies.
No image decoder, native adapter, library or dependency is changed.

## Independent regression coverage

The maintained fixture now checks every tile's actual emitted triangle UVs against
four explicit expected corner tables derived from the source image upload and
shader matrices, independently of the production UV expression. The pinned block
exercises all four flag combinations: **34 normal, 56 rotated, 150 flipped and
16 rotated/flipped** tiles.

The pre-fix production snapshot failed **exactly 256 checks**, all ground image
orientation checks. Its other **915** checks, including tile positions, passed.
This exposes the boundary missed by the original position-only tests.
