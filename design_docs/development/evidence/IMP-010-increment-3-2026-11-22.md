## Implemented scope

`world.variants` is an adapter in the existing definition registry. It registers
before reader preparation and publishes in the existing exact-ticket CORE menu
transaction. No registry, package loader, runtime selection store or post-durable
publication callback was added. Candidate indexes clear/rebuild coherently;
rejected or omitted contributions never become usable published definitions.

Installed definitions and defaults have explicit originating identities and
typed location/layout, block-placement or building targets. Whole-layout and
complete-block alternatives reuse the accepted layout APIs. Retained occurrence
IDs remain anchored to the requested layout; selected alternate definition IDs
and provenance stay distinct. Repeated blocks and building contexts resolve
independently. Raw frames, parent chains, purpose markers, doors and action links
retain the accepted validation and resource handoff.

Queries carry the exact committed content token, full layout identity, explicit
root intent, scoped selections, required records and optional structural mapping
requirements. DATA stores no caller selection. Unknown/missing/invalid required
content fails, without baseline substitution or a prior query's state. Reset
validates a baseline/default proposal and commits no selection or transition.
Explicit placement intent overrides broader defaults; ambiguous applicable
defaults reject instead of inventing a location/global hierarchy.

Add/replace/patch use actual shipped/folder/ZIP/loose intake. Replacements retain
declaration IDs, kind and target; patches replace complete permitted fields.
Defaults lose their variant effect only through an explicit baseline choice.
The fixture exercises one default's complete four-tier provenance chain,
including actual ZIP replacement, separately from placement specificity.
An earlier unresolved reference repaired by the winning ZIP patch is accepted;
an unresolved final winner, missing target or remaining reference after omission
rejects the complete candidate.

Compatibility receipts bind the selected variant and applied occurrence scope to
source/target definition IDs, canonical decoded-payload hashes, input publication
receipts, provider/contributor provenance and published-value hashes. Retained
record edits and explicit mappings are checked independently. Missing, colliding,
obsolete, wrong-scope, wrong-type/purpose and changed-door-role mappings reject.
Building mappings stay inside the declared building. These checks do not certify
real SAVE, LOC, QUEST or persistent-object compatibility and perform no migration.

## Supported limits and real-owner obligations

Building defaults, arbitrary cross-level merges and multiple edited buildings in
one placement are unsupported. Edited building alternatives use complete authored
RMB source/target definitions with identical outside-building envelopes; classic
source to authored building-local editing is unsupported. A classic block can
instead use a complete placement alternative. Incompatible containing/building
selections fail rather than repairing a partial hybrid.

WORLD/LOC still own actual selections, transitions, live assembly, cancellation,
recovery and runtime cache coordination. MOVE owns geometry/collision/placement.
QUEST/action and persistent-object owners must validate bindings. SAVE must define
required selection representation, early restore, migrations, compatibility and
save-during-transition timing. CORE-opening and M1 gates remain open. Controlled
sequential-session and restore-order probes establish only DATA's statelessness
and pre-reconstruction validation interface. No actual transition, reconstruction,
player entry, action execution, geometry or save functionality is claimed.
