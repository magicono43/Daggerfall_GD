## Precision and lifetime

Native time is a nonnegative signed-64-bit whole game-millisecond integer.
Eligible input uses integer simulation nanoseconds after CORE rate; calendar
rates use positive millionths, 0.000001..1,000,000 at six decimal places.
TIME retains an integer fraction in 10^−12 game-millisecond units. Exact integer
split/combine accounting and restore equivalence are qualified. The stock float
physics boundary quantizes once to the nearest eligible nanosecond; positive
sub-half-nanosecond input explicitly rejects. Float input retains its own binary
precision; use the integer boundary for exact long durations. No floating epoch
or full-range microsecond timestamp is constructed.

Ordinary receipts retain six packed int64 facts and reconstruct detached retry
outcomes. They retire with the session; current-session history remains retained.
Long-session receipt compaction is not qualified. Provider recreation changes
generation; old captures cannot become current. Session disposal also clears
provider/death-authority references, fixing a cycle exposed by the new controlled
entry fixture. Optional observers receive read-only committed scope/operation
outcomes; fraction-only changes emit no whole-time transition.

The versioned seven-field settled owner payload preserves exact timestamp and
fraction. Canonical compatibility includes fixed numeric and weekday/season
semantics; compatible start/rate-only overrides cannot rewrite restored instants
or absolute deadlines. Unknown versions, malformed fields, incompatible semantics
and unsupported in-progress state reject. This is no native SAVE coordinator,
durable activity reconciliation or milestone SAVE qualification.
