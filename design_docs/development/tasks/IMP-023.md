## Approved restore increments

The user approved this breakdown on 2026-11-18.

1. **Exact-generation preflight.** Resolve the selected committed generation and immutable restore input from IMP-022. Validate format and migrations, required content/providers, payload identities and references checkable before reconstruction. Return reasoned rejection without changing the outgoing session.
2. **Reconstruction and linking.** CORE begins replacement only after accepted preflight. Restore early context, prepare required geometry, hydrate owner records and register stable identities under the new scope. Resolve required references and committed placement against ready collision. Missing required registration or invalid pose follows explicit recovery.
3. **Completion.** Rebuild owner-derived state and supported UI, clear old physical input and publish one Session Restored result after required phases complete. Release load-owned holds only. On failure after replacement, perform safe cleanup and independent recovery UI; failed cleanup keeps subsequent entry gated.

## Acceptance

- Save the M2 room fixture after moving the actor, changing inventory, damaging an enemy and looting a corpse. Reload and compare each authoritative value, identity and custody relationship.
- Reject missing required content, unsupported schema and duplicate IDs during preflight. Assert identical outgoing session identity, pose, inventory and holds and zero new grants.
- Fail geometry preparation, required registration or placement after replacement begins. Assert safe cleanup/recovery and no Session Restored outcome. Fail cleanup separately and verify new entry remains blocked.
- Deliver duplicate and stale participant callbacks. Assert one terminal result and no changes to the replacement scope.
- Restore a supported modal hold and assert completing load does not release it. Verify stale attack and load-trigger input cannot execute on return.
- At the named extensions, verify live door/action, quest/world, effect and mod references under the same phases, including explicit required-data rejection.
- Verify the accepted and rejected outcomes specified by the linked feature criteria; record which criteria are covered by owner tests and which require a milestone integration run.
- Confirm that required handoff results reach the expected consumer and that rejected or obsolete input leaves committed state consistent under the approved failure policy.
