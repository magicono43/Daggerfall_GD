## Approved authoring increments

The user approved this breakdown on 2026-11-18.

1. **Exterior blocks.** Edit native blocks or copies of supported classic data in an isolated workspace. Support buildings/scenery, ground tiles and reusable groups under DEV-011.
2. **World layouts.** Arrange settlements and edit supported interior/dungeon objects, entrances, markers and action links. Include new-location creation and terrain shaping under DEV-012. Distinguish reusable variant scope from placement-specific edits.
3. **Validation/compatibility.** Preserve retained record IDs and allocate stable IDs for new authored records. Use runtime validators for assets, required links, entrances/routes and context. Validate explicit mappings before claiming compatibility for changed persistent records. Valid incompatible variants follow approved save recovery.

## Workspace fixture and integration

Use one copied exterior block, one interior/dungeon variant and a new-location draft with approach terrain. Save unfinished drafts separately from playable export. Preview through IMP-054 and validate through DATA/LOC/WORLD's actual schemas and context. Missing required context remains explicit; a partial editor check cannot bypass runtime readiness.

IMP-051 supplies variant/package integration, IMP-057 real terrain/seam checks, IMP-026 stable discovery and IMP-023 required save mappings. Export cannot mutate original source files or hot-reload locked content.

## Constraints and readiness

Planning-ready for the approved three increments. Target Windows first on Godot 4.7.2. Execution waits for IMP-026/051/054/057 and authorization. Concrete editor layout and draft representation remain implementation choices within DEV-011/012.

## Acceptance

- Edit and save an unfinished exterior-block draft, then complete it and validate playable export against the runtime loader.
- Apply reusable and placement-specific variants to two occurrences. Verify declared scope and retained/new record identities.
- Break a required entrance or action link and assert export rejection with referring/target diagnostics. Missing route context is reported explicitly.
- Create a new-location/terrain draft and verify its approach and entrance with actual WORLD/LOC validators before playable acceptance.
- Change a persistent record and test valid mapping versus declared incompatibility. Only the validated mapping can claim affected save compatibility.
- Reopen drafts and export packages without modifying original data or current locked gameplay content.
- Verify the accepted and rejected outcomes specified by the linked feature criteria; record which criteria are covered by owner tests and which require a milestone integration run.
- Confirm that required handoff results reach the expected consumer and that rejected or obsolete input leaves committed state consistent under the approved failure policy.
