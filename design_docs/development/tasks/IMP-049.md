## Approved encounter increments

The user approved this breakdown on 2026-11-18.

1. **Opportunity admission.** CORE/NPC accept encounter opportunities under the approved clock/activity context with stable occurrence identity. Validate current session, scope and eligibility before drawing or placing.
2. **Selection/placement.** Resolve approved RULE-020/NPC-006 selection using the declared purpose source. Retain resolved choice for supported technical retry. NPC/MOVE validate actual actor placement against ready geometry and publish success only on commitment.
3. **Interruption.** Return encounter/threat result and actual timing to the activity owner. Rest/travel stops at its committed interruption point and retains completed work. Duplicate opportunities or stale placement results cannot create a second encounter.

## Encounter fixture and integration

Use a controlled seed, timestamp/activity context and encounter table with valid and unsuitable placement candidates. Distinguish no eligible encounter, rejected placement, committed encounter and technical failure. Apply the source feature's draw/retry rules for each outcome.

IMP-020 supplies actual actor setup, IMP-025 geography and placement context, IMP-039 rest interruption and IMP-059 travel interruption. Ordinary gameplay, rest and travel use their approved occurrence policies and never infer one universal encounter cadence.

## Acceptance

- Admit a known eligible opportunity with controlled seed and compare selection/draw count. Reject stale or ineligible scope without an unauthorized draw.
- Select a valid and an unsuitable placement. Assert ready actor count and distinct no-encounter/rejection/failure outcomes under the approved policy.
- Deliver the same committed opportunity twice and assert one encounter. Retire the session while placement is pending and reject the late result.
- Interrupt rest at the fixture timestamp and compare actual elapsed work and threat outcome. At IMP-059 run the same owner handoff for travel without future-interval effects.
- Retry a supported technical failure with retained selection and compare against the approved outcome policy without duplicate placement.
- Verify the accepted and rejected outcomes specified by the linked feature criteria; record which criteria are covered by owner tests and which require a milestone integration run.
- Confirm that required handoff results reach the expected consumer and that rejected or obsolete input leaves committed state consistent under the approved failure policy.
