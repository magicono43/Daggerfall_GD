## Delivery increments and interfaces

The user approved this breakdown on 2026-11-18. Each increment uses production interfaces and has separate acceptance before the next increment integrates.

1. **Discovery and selection.** MOD returns package candidates with stable IDs, versions, declared dependencies, capability metadata and source provenance. Resolve duplicate candidates according to MOD-001 before planning dependencies. Maintain pending enabled selection and preferred order separately from the published configuration. Exercise accepted candidates, duplicate choices and an invalid manifest through setup.
2. **Dependency planning.** Resolve the enabled plan with required, optional and presence-only relationships under MOD-003. Return blocking errors with the dependent/provider and reason, optional-integration warnings, and complete cycle paths. Auto-sort produces a preview; explicit acceptance updates pending order. Use fixture packages A, B and C: verify provider-first order, a missing required provider, an incompatible version, a required cycle, and optional-edge suppression. Presence-only relationships validate availability/version without adding an order edge.
3. **Definition publication.** DATA takes the validated package plan and adapter-declared operations, schemas and references. Build an isolated candidate with winning and contributing provenance. Exercise shipped defaults, ordered mod replacement and an explicit loose override. An add collision or invalid late patch rejects its entire contribution. Revalidate the resulting candidate after explicit omission. Failure stays in recovery and publishes no invalid state. Enter the main menu only after publication succeeds. Returning to title or changing character preserves the run's locked definitions and package order.

## Constraints and readiness

Planning-ready for the data-only delivery confirmed by the user. Target Windows first on Godot 4.7.2. IMP-002 and IMP-004's assigned increments are delivered and user-accepted; execution awaits explicit IMP-005 authorization. Test adapters provide bounded schemas for initial publication fixtures. Actual text, media and world schemas integrate with IMP-007/008/009/010. Executable lifecycle and provider registrations integrate with IMP-050/051 under GAD-10. Those integrations retain the same candidate-plan and publication boundary.

IMP-001 owns setup routing, IMP-004 owns classic-source validation and application reader lifetime, MOD owns package selection/order, and DATA owns resolved definitions. The published content and plan are read-only to normal gameplay consumers. A character load cannot activate pending configuration.
