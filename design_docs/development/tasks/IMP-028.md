## Approved quest execution increments

The user approved this breakdown on 2026-11-18.

1. **Grammar and registry.** QUEST parses resolved DATA sources and binds supported command declarations with provider identity and source spans. Reject unknown required commands and ambiguous grammar. Validation does not execute gameplay actions or consume live generation draws.
2. **Task execution.** Maintain stable quest/task/run/action identity, admitted immediate/scheduled starts, triggers and rearming under QUEST-008/009. Execute in declared order with retained owner outcomes. Legitimate authored repeats obtain new run identity.
3. **Clocks and completion.** Register deadlines and due work through TIME. Apply cutoff semantics and required closing-work gates before terminal quest state. Retain globals and tombstones under QUEST-011/020.
4. **Fault recovery.** Distinguish authored failure from technical recovery. Preserve committed action outcomes and pending obligations with the applicable owner receipt. Resume only authorized outstanding work. Produce one recovery episode notice state and bounded diagnostic context under QUEST-023.

## Acceptance

- Parse valid immediate/scheduled scripts and reject unknown required commands or malformed grammar with source span/provider context. Assert validation produces no live quest effects or RNG draws.
- Trigger and rearm a task under QUEST-009. Verify stable execution order and distinct identities for a legitimate repeated run. Duplicate delivery of the same action cannot repeat its owner effect.
- Commit the first fixture action and fail the second. Assert recovery state retains the committed receipt and required closing work keeps the quest nonterminal. Retry outstanding work and assert one final outcome.
- Advance through a deadline with an uncommitted hand-in at the exact cutoff. Verify expiry precedence using the TIME contract.
- Restore globals/tombstones through the controlled projection and verify a completed one-time quest does not restart. Close actual persistence and recovery-notice behavior with IMP-038/030.
- At IMP-053 verify read-only inspection and isolated author tests reuse these facts without advancing conditions or invoking actions.
- Verify the accepted and rejected outcomes specified by the linked feature criteria; record which criteria are covered by owner tests and which require a milestone integration run.
- Confirm that required handoff results reach the expected consumer and that rejected or obsolete input leaves committed state consistent under the approved failure policy.
