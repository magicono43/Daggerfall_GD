## Reader and validation contract

Approved by the user on 2026-11-18.

- Each content adapter declares required sources and supported header/index checks. Compose the startup manifest from the registered required adapters. Return source path, manifest entry and failure category when a check fails. Filename and supported-format bounds govern acceptance; compatible modified contents remain supported.
- Publish read access only after all required readers initialize. Distinguish ready access, missing record, unavailable source, and malformed or unsupported data. Include source and record identity in failures. Consumers decide recovery under their approved specifications. Cleanup failed initialization before retry.
- Keep readers and reusable indexes application-scoped across menus and characters. Read source files on demand through this access contract. Adapter-specific decoding and record schemas are delivered and verified with IMP-007 through IMP-010 and IMP-061. Their manifest declarations participate before normal entry when their required capability is enabled.
- Use the user-supplied classic data as the success fixture, with its path supplied locally at invocation. Available locations are `C:\Games\Daggerfall\arena2` and repository-relative `base_data_files/arena2/`; select and record the actual source used. Directory presence does not establish format validity or equivalence between copies. Keep both sources read-only and do not hardcode a machine-specific path in production defaults. Generate negative cases in disposable test storage. Record the selected source file and record evidence for each successful adapter fixture, and verify the source is opened read-only.

- Resolve both the ARENA2 folder and its immediate parent through the approved selection rules. Initialize the required manifest against the supplied installation. In disposable fixtures remove one required file, empty it, truncate a supported header and point an index outside its file. Each case returns its file and failure reason and leaves reader readiness false. Verify a missing record is distinct from an unavailable source. Reuse readers after a character change and clean failed initialization before retry.
- Verify the accepted and rejected outcomes specified by the linked feature criteria; record which criteria are covered by owner tests and which require a milestone integration run.
- Confirm that required handoff results reach the expected consumer and that rejected or obsolete input leaves committed state consistent under the approved failure policy.
