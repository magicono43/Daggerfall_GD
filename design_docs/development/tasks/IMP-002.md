## Session and UI handoff

- CORE admits one session-changing operation for the selected intent and immutable selection. Return busy immediately for a conflicting request. Accept provider results only for the current operation and scope. The provider returns prepared input or a reason for failure. Cancellation during preflight preserves the outgoing session. After replacement starts, CORE waits for readiness or runs cleanup/recovery. Emit one terminal success, failure or cancellation per admitted operation. A cleanup failure keeps new sessions gated.
- CORE maintains independent operation/session-scoped simulation, gameplay-input and presentation holds. UI owns the active window, focus, modal choice/cancellation and shortcut routing. Each requester releases only its own hold. Closing a modal consumes its closing input and restores the eligible underlying focus. Dispose session-scoped windows, holds and subscriptions when retiring a session.
- First increment uses an ordinary title/pause/modal path and a controlled provider that can hold preflight, finish preparation, report replacement readiness or fail cleanup. Use the same CORE request and UI window interfaces with real providers. IMP-015/036 close real title-to-character entry, IMP-023 closes native restore, IMP-011 closes gameplay input delivery, and IMP-051 closes provider-qualified window replacement. CORE remains the lifecycle owner throughout.
