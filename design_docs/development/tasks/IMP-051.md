## Approved extension increments

The user approved this breakdown on 2026-11-18.

1. **Content.** Resolve patches, world variants and definitions through DATA and the relevant owner schemas. Preserve contribution boundaries, stable identities and source provenance under the locked plan.
2. **Registrations.** Owners define and validate custom item/effect/verb/service, activation, formula and UI contracts. MOD coordinates eligible providers, explicit replacement choices, pre-menu registration and owned teardown. Register into a candidate registry before publication.
3. **Mod payloads.** Identify each payload by stable package ID and mod-owned version inside the native save generation. Required providers/versions and supported migrations validate before replacement. Restore owner facts without replaying registration or committed gameplay effects.

## Acceptance

- Register one provider-backed fixture per enabled family and compare selected provider, precedence and outcome against its owner contract.
- Submit conflicting or invalid registrations. Assert explicit rejection/selection recovery and no partial published registry.
- Fail activation after owned resources exist and verify checked teardown. Unsafe cleanup follows MOD-005 restart recovery.
- Save mod state, rename the package file while retaining identity and reload compatible payloads. Verify stable package binding and no repeated effects.
- Remove a required provider or change to an unsupported payload version. Reject preflight; exercise a declared migration separately.
- Restore supported pending mod work with receipts and assert only authorized outstanding mutations resume.
- Verify the accepted and rejected outcomes specified by the linked feature criteria; record which criteria are covered by owner tests and which require a milestone integration run.
- Confirm that required handoff results reach the expected consumer and that rejected or obsolete input leaves committed state consistent under the approved failure policy.
