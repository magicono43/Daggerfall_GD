## Approved input delivery increments

The user approved this scope and controller policy on 2026-11-18.

1. **Logical delivery.** Preserve brief taps and ordered input edges, aggregate overlapping bindings and distinguish cancellation from deliberate release. Scope pending input to the eligible CORE context and session. Test focus loss, loading and active-controller disconnect through requester-owned gates.
2. **Binding configuration.** Provide application-wide staged bindings with the approved two keyboard/mouse and two controller slots per discrete gameplay action. Validate overlapping contexts and explicit Replace/Cancel conflicts. Keep recovery inputs reserved. Apply the candidate coherently and report persistence failure separately from effective controls.
3. **View and cursor.** Use approved mouse, keyboard-look and controller precedence. Preserve actual visible-facing aim and clear pending look on handoffs. Verify center view, cursor entry/exit, focus return and gesture ownership without stale motion or held-action activation.

Support one selected gameplay controller initially. When several are connected, selection is explicit. Keep separate configurable movement and look deadzones. Controller connection alone cannot clear disconnect suspension. Numeric defaults, supported binding inputs and action mappings are specified in the subsequent tuning inventory.

The user approved bounded-input overflow handling on 2026-11-18. Overflow invalidates unfinished gameplay input, reports the failure and requires fresh presses before further delivery. Report already-delivered outcomes separately from cancelled pending work. Do not reinterpret cancellation as a release-triggered action. Preserve independent CORE holds. Exact queue capacity is an implementation limit documented and exercised by filling that capacity plus one input in the fixture.

The user confirmed keyboard/mouse remappings and Toggle Crouch on 2026-11-18, retaining DFU defaults for unlisted actions. See [INPUT_DEFAULTS.md](../INPUT_DEFAULTS.md). Console accepts the physical grave/tilde key with or without Shift. F7 toggles the HUD. F opens the spellbook through Cast Spell. The user also approved mouse sensitivity, trigger thresholds and controller cursor speed on 2026-11-18.

## Approved initial response defaults

The user approved these adjustable defaults on 2026-11-18.

- Radial movement deadzone 0.15 and look deadzone 0.10. Rescale magnitude linearly from zero at the applicable threshold to one at full deflection, preserving direction. Clamp resolved stick magnitude to one.
- Pitch limit ±89 degrees. Mouse and controller smoothing default off. Controller look defaults to 180 degrees/second horizontally and 120 degrees/second vertically at full eligible input. Keyboard look defaults to 90 degrees/second. Preserve independent sensitivity and vertical inversion settings.
- Select a discrete binding when its main-key press starts. Late modifier presses or releases cannot start another action from that hold. A fresh main-key press resolves against the current modifier state. Context invalidation still cancels unfinished input under MOVE-001.

Verify stick center/threshold/full deflection, equal eligible elapsed time at different frame rates, pitch bounds, and modifier changes during an existing hold. These are starting settings subject to the approved player controls and rendered acceptance.

Target Godot 4.7.2. Preserve the approved gameplay policies, including feature-specific deferrals and conditional scope. Use user-provided classic data through approved access and isolated verification fixtures. The local DFU tree is a read-only reference.

Planning-ready with the approved action map, response defaults, modifier semantics and checked input-overflow contract. Document the chosen finite queue capacity with its boundary test during implementation. Execution waits for IMP-002/003 and authorization.
