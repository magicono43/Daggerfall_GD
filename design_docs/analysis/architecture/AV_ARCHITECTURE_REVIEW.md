# AV architecture review

Covers AV-001 through AV-013 in the [feature catalog](../systems/AV_FEATURE_CATALOG.md). Static evidence comes from the local DFU 1.1.1 Release snapshot. Source paths are relative to Assets/Scripts. See the [repository overview](../00_REPOSITORY_OVERVIEW.md) for revision limits.

## Existing architecture

### World rendering and environment · AV-001–004

MeshReader.GetMesh creates engine meshes and resolves materials by submesh. MaterialReader.GetMaterial and ChangeClimate select material variants and reuse cached resources. Internal/DaggerfallBillboardBatch.cs groups billboard geometry and uses jobs and mesh buffers to build and upload batches. Animation updates can replace UV data without rebuilding the whole mesh. Preserve shared resources and this distinction between static geometry and animated frame data. Cache scope must include conversion and climate inputs where they change output. Peak memory, upload cost and batch size trade-offs are unmeasured.

Internal/DaggerfallSky.cs applies time and space context, loads day/night imagery, draws the sky and explicitly destroys replaced textures. SunlightManager, WeatherManager, UnderwaterFog and PlayerEnterExit contribute to lighting and fog. The distinction between time/weather selection and rendering is useful. Global camera, lighting and fog state make the result sensitive to which system writes during a transition. Establish precedence for exterior, interior and submerged views. See the [TIME review](TIME_ARCHITECTURE_REVIEW.md) for restore sequencing. No scene or shader execution was performed.

### Retro composition and settings · AV-005–006

Utility/RetroRenderer.cs UpdateRenderTarget switches between separate world-only and HUD-inclusive low-resolution targets and adjusts camera targets, including the sky camera. RetroPresentation.OnRenderImage blits the configured retro source to the screen when enabled. This expresses several intentional composition choices, including whether the HUD is pixelated. It relies on Unity camera targets, callback order and global settings. Preserve pass order, filtering, aspect treatment and the distinction between world and HUD resolution in a Godot rendering prototype. Do not assume a one-to-one mapping from OnRenderImage.

RetroRenderer.InitLut, UpdateDepthProcessMaterial and TogglePostprocessing configure palette and depth processing. GameEffectsConfigWindow.AddCorePages and AddConfigPage expose effect settings and extension pages. Runtime effect parameters and UI are useful independent seams. Treat target swaps, post-processing enablement and resource disposal as one lifecycle. Validate missing textures or shaders with a usable fallback. Memory and render pass costs need representative measurements.

### First-person and impact feedback · AV-007–008

Game/FPSWeapon.cs loads an atlas and draws the first-person weapon through OnGUI. WeaponManager uses GetHitFrame to decide damage commitment. FPSSpellCasting emits a release callback used by EntityEffectManager. These hooks align effects with visible animations but also make gameplay depend on presentation progress. Preserve timing through explicit markers with a single-commit contract and test interruption or skipped frames. See the [COMBAT](COMBAT_ARCHITECTURE_REVIEW.md) and [MAGIC](MAGIC_ARCHITECTURE_REVIEW.md) reviews.

DaggerfallMissile drives billboard animation, dynamic light and impact sound alongside payload delivery. EnemyBlood, PlayerFootsteps and HeadBobber provide separate cues. Use resolved movement and combat outcomes as inputs to these effects. Fall damage currently crosses a string message into the footsteps component, as detailed in the [MOVE review](MOVE_ARCHITECTURE_REVIEW.md). Mod visuals and alternate presentation should be able to consume the same outcome without changing its gameplay consequences.

### Audio, music and cinematics · AV-009–013

Internal/DaggerfallAudioSource.cs provides sound selection, one-shots and spatial playback over engine sources. SoundReader caches decoded clips. AmbientEffectsPlayer selects context presets and controls loops, lightning and spot effects. It subscribes to global cinematic start/end events and uses them to stop loops and toggle IsMuted. Its water cues use shared DFRandom and Unity random draws. This is confirmed coupling between presentation and shared generators. Effects on later simulation rolls depend on call order. Preserve ambience priorities and use a local presentation random source if reproducibility matters.

SongManager separates context and playlist selection from playback in DaggerfallSongPlayer. The latter supports replacement clips and MIDI, using the sequencer and SoundFont synthesis code under AudioSynthesis. Play checks InitSynth before trying a replacement clip, so a failed synth initialization also prevents the clip lookup on that path. OnAudioFilterRead reads shared playback state, can resize the sample buffer and catches exceptions described in comments as possible during startup/shutdown. These are confirmed implementation choices. Actual dropout rate, allocation cost and thread behavior were not measured. Keep backend state and resource ownership explicit.

DaggerfallVidPlayerWindow.Setup tries a replacement through VideoReplacement before using DaggerfallVideo. Update handles native and custom playback, skip and end conditions, disposes the player, restores cursor behavior and publishes finished/end events. This supports replacement content while retaining classic playback. Both normal finish and skip share the same completion notification. The inspected cleanup is in the Update completion paths. Verify external window removal and decoder failure before relying on paired global events. A consumer like AmbientEffectsPlayer depends on receiving the end notification to clear its cinematic mute.

## Comparison

| Concern | DFU | Proposed Godot design |
| --- | --- | --- |
| World rendering | Resource readers, Unity batches and shared environment state | AV-owned resources and explicit environment inputs |
| Retro output | Camera target switching and image callback | Explicit viewport composition with optional HUD pixelation |
| Feedback | Some gameplay commits depend on presentation frames | Owner-committed outcomes and controlled timing markers |
| Audio and video | Context selection, replacement paths and playback callbacks | Independent backends and explicit playback completion |

Verify climate/material changes, scene re-entry, underwater lighting, retro/HUD modes, palette/depth effects and interrupted action cues. Test replacement playback with unavailable synthesis, repeated MIDI start/stop, and cinematic skip, failure and external removal. Profile GPU uploads, target memory and audio callback behavior before optimizing. No runtime, profiling or classic parity tests were performed.
