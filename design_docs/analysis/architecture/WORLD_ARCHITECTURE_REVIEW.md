# WORLD architecture review

Covers WORLD-001 through WORLD-018 in the [feature catalog](../systems/WORLD_FEATURE_CATALOG.md). Evidence comes from static inspection of the local DFU 1.1.1 Release snapshot. The [repository overview](../00_REPOSITORY_OVERVIEW.md) records revision limits. Source paths are relative to Assets/Scripts. Runtime sequencing, profiling and classic parity remain open.

## Existing architecture

### Coordinates, rebasing and arrival · WORLD-001–004

Terrain/StreamingWorld.cs synchronizes the local player transform, world coordinates and map pixels. API/MapsFile.cs provides the classic coordinate conversions. Utility/FloatingOrigin.cs FixedUpdate skips shifts during initialization, then offsets the player controller and streaming children, adjusts enemy grounded references and broadcasts the offset. This keeps local physics near the origin and lets cached positions follow the shift. It also means components holding local positions must participate in the rebase contract. Independent frame and physics updates make event order at a pixel crossing worth testing.

TeleportToMapPixel writes GPS world coordinates, calls UpdateWorldInfo, records the reposition policy, calls InitWorld, clears fall state and emits OnTeleportToCoordinates. InitWorld resets the player to the origin, clears streaming state and sets init while the terrain and final placement are still pending. The teleport event therefore reports a requested destination before placement is ready. Some callers wait on IsInit or a related respawn flag. Distinguish request, world readiness and placement completion. Preserve explicit arrival policies for exact world position, offsets, location markers and dungeon exits. See StreamingWorld.TeleportToWorldCoordinates, PositionPlayerToLocation and PositionPlayerToDungeonExit and the [MOVE review](MOVE_ARCHITECTURE_REVIEW.md).

### Streaming residency and cleanup · WORLD-005–007

StreamingWorld manages a terrain window around the active pixel. UpdateTerrains, PlaceTerrain and CollectTerrains reuse descriptors and deactivate out-of-range terrain and billboard objects. A full collect invalidates pixel coordinates to avoid reusing stale slots. UpdateNeighbours reconnects terrain after placement and collection. Pooling is a useful response to predictable working-set size. Tuning the radius changes object count, data buffers and activation work. Measure memory and crossing spikes before changing pool or radius behavior.

UpdateLocations and CreateLocationGameObject bind exterior content to terrain. The current building directory and city navigation are exposed to MOVE and NPC. TrackLooseObject records spawned objects by map pixel, while CollectLooseObjects deactivates them, removes tracking and schedules destruction. The recursive iterator call inside DestroyGameObjectIterative is neither enumerated nor scheduled, so it does not execute the child iterator bodies. The root still reaches its own destruction, but the code does not deliver the documented per-child teardown. Frame cost and object-lifetime consequences need runtime checks. Explicitly distinguish pooled, transient and save-backed objects so a residency change cannot silently discard durable state.

### Terrain generation and presentation · WORLD-008–011

Terrain/DefaultTerrainSampler.cs uses classic height records from WoodsFile plus detail sampling and exposes a scheduled job path. Terrain/TerrainTexturing.cs assigns tiles and converts water transitions. DaggerfallTerrain owns per-pixel updates and promotion to engine terrain. The streaming completion path calls JobHandle.Complete, completes map data, promotes it and reactivates terrain. Its coroutine waits for completion before promotion. The division between sampling, tile classification and engine resource creation is useful. JobHandle, NativeArray and engine terrain APIs are implementation-specific. The coroutine captures a descriptor and later promotes it, so rapid teleport, pool reuse and teardown should be tested for stale results and buffer cleanup. No stale publication or leak was reproduced.

Preserve shared edge sampling, neighbor update order and water classification as separate contracts. Gameplay movement reads tile state, so visual tile changes must preserve collision and water semantics where required. TerrainNature.LayoutNature seeds Unity's shared random generator with a terrain key. This makes the draw sequence for a tile reproducible with fixed inputs, but the reseed changes the generator used by other systems. Nature placement includes mod mesh replacement and billboard batching. Keep seeded placement and presentation replacement distinct. See Terrain/TerrainNature.cs, Terrain/TerrainHelper.cs and Utility/AssetInjection/MeshReplacement.cs.

### Location context, discovery and queries · WORLD-012–018

Internal/PlayerGPS.cs owns derived region, climate and location context. UpdateWorldInfo and RaiseEvents feed consumers, and CalculateWorldLocationRect and PlayerLocationRectCheck determine bounds and transitions. Keep map-pixel identity separate from an actual location-boundary crossing. Context also carries race and regional faction lookup. A consumer can observe a new GPS context while streaming and actor placement are pending. The current discovery and arrival event order is a cross-system contract for QUEST, LAW, TIME and UI.

PlayerGPS owns location and building discovery, custom names and lockpick-attempt fields. Game/ExteriorAutomap.cs derives textures, labels and marker positions from exterior content and discovery, and has its own render-resource lifecycle. This provides a useful separation between persistent exploration facts and view composition. Map texture/nameplate rebuild costs are unmeasured. PlayerGPS.UpdateNearbyObjects clears and refills a list from active actor and loot registries, computing distance and flags. This avoids a full scene search but scales with active population and refresh frequency. Measure before indexing and specify query freshness if gameplay depends on it.

GetDiscoverySaveData calls RemoveUnnamedResidencesFromDiscoveryData before returning the live discovery dictionary. This is a confirmed mutation during save-data collection and gives the serializer a mutable reference. RestoreDiscoveryData adopts the supplied dictionary and removes legacy entries with mapPixelID zero. Keep the compatibility intent and make pruning explicit. Game/Serialization/SaveLoadManager.cs restores discovery and, for interiors, world compensation height before placement. ExteriorAutomap has a separate restore hook. Verify old keys, renamed buildings, interior compensation and failed reconstruction. Do not infer save compatibility from matching field names alone.

## Comparison

| Concern | DFU | Proposed Godot design |
| --- | --- | --- |
| Coordinates and arrival | GPS and streaming synchronization, offset events and readiness flags | Explicit coordinate ownership, rebasing and placement completion |
| Terrain and residency | Recycled Unity objects with job promotion | Tile lifecycle and request-aware promotion through engine adapters |
| Generation and queries | Classic sampling, shared seeded nature draws and active registry scans | Testable tile inputs, local generation draws and measured query budgets |
| Exploration persistence | GPS discovery dictionary and separate automap state | Stable exploration records with explicit save projection and derived views |

Verify repeated teleports and rebases, long diagonal crossings, rapid tile reuse, cancellation, terrain seams, water transitions and arrival fall-state reset. Exercise location events before and after readiness, discovery saves with legacy keys, building rename persistence and nearby queries across unloading. Profile terrain promotion, cleanup and map rebuilds before optimizing. No runtime, profiling or classic parity tests were performed.
