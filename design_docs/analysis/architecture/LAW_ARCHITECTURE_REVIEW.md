# LAW architecture review

Covers LAW-001 through LAW-016 in the [feature catalog](../systems/LAW_FEATURE_CATALOG.md). Evidence comes from static inspection of the local DFU 1.1.1 Release snapshot. See the [repository overview](../00_REPOSITORY_OVERVIEW.md) for revision limits. Paths are relative to Assets/Scripts. Classic parity and player-visible behavior remain unverified.

## Existing architecture

### Incidents, standing and cross-system penalties · LAW-001–006, 010

Game/Entities/PlayerEntity.cs owns a single Crimes value, regional LegalRep and SeverePunishmentFlags, and arrest and surrender state. SetCrimeCommitted checks a racial override for suppression and raises OnCrimeUpdate, including on clear, except during save load. The delayed pursuit path in Update assigns the backing field directly, bypassing the setter's suppression and notification logic. That distinction is confirmed in source. It may be deliberate for warrants, but callers and mod subscribers need to know which transitions they observe.

Detection belongs to several entry points. Game/PlayerActivate.cs handles forced entry, trespass and pickpocketing. DaggerfallInventoryWindow and DaggerfallTradeWindow handle private property and shoplifting. WeaponManager handles civilian hits, and DaggerfallRestWindow can trigger guards for vagrancy. These owners know the target, location and action result, which is worth preserving. Each can also drive the legal response, so the order of reporting, penalties, pursuit and UI depends on the path. Game/LoanChecker.cs instead attempts repayment, marks a default once and applies a regional standing penalty without requiring a guard encounter. Keep this distinction between an immediate incident and a durable administrative penalty.

PlayerEntity.LowerRepForCrime updates the region and propagates a separate change through the local people faction. RaiseReputationForDoingSentence uses the stored sentence-related amount for recovery. ClampLegalReputations and periodic normalization constrain legal standing separately from faction reputation. This is a useful boundary to preserve. The faction lookup's success is ignored before using the returned ID in the penalty and recovery methods. Define the fallback when a custom region lacks that faction. The crime-indexed penalty table and regional standing calculations are testable once the inputs are supplied explicitly.

### Guard deployment and arrest · LAW-007–009

PlayerEntity.SpawnCityGuards and SpawnCityGuard translate a response into physical guards, including doorway placement and converting pooled civilian guards. MakeNPCGuardsIntoEnemiesIfGuardsSpawned can convert newly available guards. This reuses existing population and placement behavior. It also couples legal decisions to live scene objects and combat state. Keep NPC ownership of placement and activation, including a defined result when no suitable placement is available.

PlayerEntity.Update uses elapsed-minute checks for pursuit under low standing or banishment. The same loop can break on an ambient encounter before processing the remaining legal checks. Both warrant conditions can run in one iteration. The loop cost scales with elapsed time and shares random consumption with encounter logic. The source does not establish an observed performance issue.

EnemyAttack handles the surrender prompt and forced-surrender path. PlayerEntity.SurrenderToCityGuards sets health to one before testing some rejection conditions, so a rejected forced surrender can still change health. The subsequent attack path may then apply damage. CourtWindow attempts exterior transition, sets Arrested, captures a crime-derived recovery amount and posts a UI message. The current sequence makes the arrest depend on live actor state and a scene transition, without a court case object carrying the charge and jurisdiction. See the [COMBAT review](COMBAT_ARCHITECTURE_REVIEW.md) for the mutable pending-hit callback.

### Trial and punishment · LAW-011–014

Game/UserInterfaceWindows/DaggerfallCourtWindow.cs owns both the court screen and the trial state machine. HandleCourtLogic reads the current charge, standing and funds, uses Dice100 and DFRandom for severity and sentence calculation, and checks Dark Brotherhood membership and rank for a rescue. GuiltyNotGuilty_OnButtonClick changes the sentence and charges gold. DebateLie_OnButtonClick uses live Etiquette or Streetwise and Personality, tallies practice and rolls a verdict. Preserve distinct plea and defense rules and explicit rounding and roll boundaries. UI callbacks currently perform the decisions and mutations, making headless testing and repeated-callback handling harder.

The base HandleCourtLogic assigns punishmentType either 0 or 2. The plea paths test for 1 to reach execution, but no assignment to 1 appears in that base implementation. Execution has a screen branch and severe flag. Its presence does not demonstrate reachability through the inspected base trial flow. Banishment sets its own flag, which the delayed pursuit loop reads. Confirm the intended severe outcomes and any subclass behavior before treating execution as a supported requirement.

### Sentence execution, release and persistence · LAW-015–016

UpdatePrisonScreen uses real-time screen updates, then advances game time in bulk, suppresses spawning and normalization and refills vitals. ReleaseFromPrison advances another four hours, clears the charge, optionally repositions the player, clears active enemies and closes the window. OnPop clears arrest/prison state and reloads court presentation. This keeps real-time pacing separate from elapsed game time, but simulation finalization depends on UI state. The broad ClearEnemies call can affect actors beyond the arrest encounter. Scope and intended consequences need fixtures. Release should define time, standing, placement and cleanup order even when a presentation or placement step fails.

Game/Serialization/SerializablePlayer.cs maps the charge, surrender-prompt flag and regional records, with a guard for older regional data. It restores the charge through its setter, while notification is suppressed during load. Game/Utility/StartGameBehaviour.cs has a separate classic import path. PlayerEntity's location and fast-travel callbacks also participate in transient crime and pursuit behavior. The reviewed native mapping establishes durable regional state and selected transient fields. It does not establish that a partially completed court window can resume after reload. Verify save eligibility, restore ordering with racial suppression, and classic regional penalties before setting a compatibility requirement.

## Comparison

| Concern | DFU | Proposed Godot design |
| --- | --- | --- |
| Incident and standing | Distributed detection and player-owned charge and regional records | Owner-reported incidents with explicit jurisdiction and legal policy |
| Pursuit and arrest | Player update, NPC placement and combat callbacks | Legal decisions with typed deployment and captured arrest context |
| Trial and release | Court window owns rolls, mutations and time/placement | Testable trial rules and ordered sentence completion |
| Persistence | Regional records and selected transient fields | Explicit durable state and a documented pending-case policy |

Verify direct and suppressed crimes, loan default idempotence, pursuit with overlapping warrant conditions, forced surrender rejection, guild rescue, plea thresholds, banishment and release. Test long time jumps and classic/native restoration with modded regions. No runtime, profiling or classic parity tests were performed.
