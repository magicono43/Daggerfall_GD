# DATA architecture review

This review covers DATA-001 through DATA-024 in the [DATA feature catalog](../systems/DATA_FEATURE_CATALOG.md). It uses static inspection of the local DFU 1.1.1 Release snapshot. The exact source commit is unavailable. Paths are relative to Assets/Scripts unless otherwise stated. Confirmed findings describe code and contracts. Runtime prevalence, classic content fidelity, memory budgets and effective mod combinations remain open. [Repository overview](../00_REPOSITORY_OVERVIEW.md)

## Existing architecture

### Source discovery and selection · DATA-001–003

DaggerfallUnity.SetupArena2Path delegates archive checks to DFValidator.ValidateArena2Folder. SetupContentReaders constructs the ContentReader façade. ContentReader.SetupReaders creates format-specific readers such as MapsFile and BlocksFile with FileUsage.UseMemory. FileProxy also supports disk-backed access and BsaFile supplies archive record access. Keep the separation between path validation, binary decoding and consumer lookup. Eager in-memory storage avoids repeated file access but can grow startup memory. Measure retained bytes and cold startup before changing modes. Reader availability is coordinated through the Unity host, making full initialization harder to exercise outside the engine. Source discovery and reader lifetime interact with CORE bootstrap.

TextAssetReader.TryRead chooses a StreamingAssets relative path first and then asks ModManager for the basename. Two different relative paths sharing a basename therefore submit the same mod lookup. ReadAll instead collects loose files and mod assets from the requested directory and returns content without provenance. It has no explicit loose-file sort. Merge applies enabled mod contributions in iteration order, optionally matching an existing record through a predicate and linear FindIndex. This supports incremental patches without copying whole tables. It also makes collision behavior depend on the consumer's selected operation. TryRead<T> calls SaveLoadManager.Deserialize, tying content decode to a persistence façade. File access, parse failure and absence need separate diagnostics. See Utility/AssetInjection/TextAssetReader.cs.

### Classic world and encounter records · DATA-004–007

MapsFile defines coordinate-to-pixel and pixel-ID transforms. ContentReader bridges those IDs to regions, locations and quest location lookup. BlocksFile decodes DFBlock records. RMBLayout and RDBLayout consume them to build exterior and dungeon objects. WoodsFile and MapsFile feed terrain samples and climate settings, while DefaultTerrainSampler and TerrainTexturing convert those inputs into terrain behavior and presentation. FlatsFile exposes flat-ID lookup, and MonsterFile and PaintFile are separate inputs behind SetupReaders. Typed format readers and a common coordinate convention are useful boundaries. Keep raw identifiers and legacy coordinate math at ingestion or in well-tested conversions. A display name or transient array position used as an authored identity would make renames and data reordering risky. The actual record populations and location/marker fidelity depend on the classic archives. Inspect API/MapsFile.cs, API/BlocksFile.cs, API/WoodsFile.cs, API/FlatsFile.cs, Utility/ContentReader.cs and the two layout classes.

### Gameplay definitions and quest inputs · DATA-008–012

- **Classes and biography (008).** ClassFile decodes DFCareer. BiogFile exposes effect and skill parsing but ApplyEffects also takes a PlayerEntity, connecting a data reader directly to live mutations. StartGameBehaviour invokes the biography path during session entry. Keeping the decoded career and biography representations is useful. Applying grants in CHAR would let the same decoded data serve previews and tests.
- **Factions (009).** FactionFile exposes ID and name dictionaries, keeps a static custom registry, merges classic SaveVars and relinks children. The graph pass is a useful explicit boundary. Exposed mutable dictionaries make it possible for a caller to bypass validation or leave secondary indexes out of sync. Definition and session-state ownership intersect at merge. See API/FactionFile.cs.
- **Items and spells (010–011).** ItemHelper.LoadItemTemplates loads packaged JSON and merges patches keyed by template index. LoadMagicItemTemplates has a separate packaged input. RegisterCustomItem links runtime types to ItemCollection deserialization. EntityEffectBroker.RebuildClassicSpellsDict merges classic records by index and converts them into effect bundle settings. Preserve legacy IDs at this boundary and explicit effect translation. Content IDs, C# registration and save restoration are coupled for custom types. Unknown effects and missing templates need domain-specific handling. See Game/Items/ItemHelper.cs, Game/MagicAndEffects/EntityEffectBroker.cs and Utility/DaggerfallSpellReader.cs.
- **Quests (012).** QuestMachine.GetQuestSourceText and GetTableSourceText read loose files and return empty arrays for missing paths after logging. QuestListsManager discovers packs and has its own source loading call sites. Independent quest scripts and lists permit authors to change content separately from execution. A missing source and a genuinely empty source share a result at those methods. QUEST should own grammar and references while DATA owns source identification. See Game/Questing/QuestMachine.cs and Game/Questing/QuestListsManager.cs.

### Localization, formatting and readable content · DATA-013–020

- **Lookup, patches and fonts (013–014, 019).** TextManager resolves runtime and default collections, offers caller reversion, and keeps locale/font registration separate from key lookup. Localized location and item names use IDs with canonical name fallback. This is a useful identity/presentation separation. Some table initialization uses WaitForCompletion. Measure startup and locale changes before treating synchronous waits as a performance problem. StringTablePatcher implements Unity's ITablePostprocessor and adds or replaces entries in row order. StringTableCSVParser.Load selects a mod before StreamingAssets, the reverse of TextAssetReader.TryRead. LoadDictionary rejects duplicate rows through Dictionary.Add, while the patcher can overwrite a key with a later row. These are confirmed differences. Locale assets and glyph coverage still need fixtures. See Game/TextManager.cs, Game/StringTablePatcher.cs, Game/StringTableCSVParser.cs, Game/UserInterface/DaggerfallFont.cs and API/FntFile.cs.
- **Classic tokens and authoring (015, 020).** TextProvider and its default/fallback implementations give consumers a replaceable provider over classic formatting tokens. TextFile.ReadTokens parses the original records. DaggerfallStringTableImporter converts between tokens and translator-facing markup with distinct cases for justification, position, separators and cursor markers. Keeping structured tokens preserves format semantics. The two conversion directions need shared round-trip fixtures, especially for escaped literals and segmented records. Source inspection alone does not establish round-trip fidelity. See Utility/TextProvider.cs, Utility/FallbackTextProvider.cs, API/TextFile.cs and Localization/DaggerfallStringTableImporter.cs.
- **Macros and names (016–017).** MacroHelper and QuestMacroHelper expand dynamic text with context providers and handler delegates. Several MacroHelper handlers also look up GameManager state or assign the global DFRandom seed, including ruler and random race/name paths. This is confirmed shared-state access from presentation-oriented code. The impact on subsequent gameplay randomness depends on call order. NameHelper and MapsFile.GetNameBankOfRegion separate a name bank from the displayed text, but classic bank and seed behavior need fixtures. See Utility/MacroHelper.cs, Utility/IMacroContextProvider.cs and Game/Utility/NameHelper.cs.
- **Books (018).** LocalizedBook separates localized and classic open paths. The classic path can import a replacement before opening the original BookFile. This preserves a classic fallback while allowing new book text. Book content, localized title and stable book identity need separate resolution. Verify behavior for absent translations, malformed replacements and a modded classic book. See Game/LocalizedBook.cs and Utility/AssetInjection/BookReplacement.cs.

### Media adapters and world variants · DATA-021–024

MeshReader builds engine meshes from Arch3dFile data and has a model cache. MaterialReader and TextureReader create engine textures, atlases and materials from decoded images and settings. MaterialReader supports cache groups and stale material purging. SoundReader caches clips by sound index, while song/movie paths and asset replacement helpers handle separate formats. These adapters avoid repeating decode and conversion. Cache scope and invalidation depend on format and owner. A source switch or climate/settings change needs a defined cache policy. Peak memory, duplicate uploads and hitch frequency are unknown. Keep mesh, texture and audio construction at the engine boundary. See MeshReader.cs, MaterialReader.cs, Utility/TextureReader.cs, SoundReader.cs, Internal/DaggerfallSongPlayer.cs and Utility/AssetInjection media replacement helpers.

WorldDataReplacement handles overrides, while WorldDataVariants maintains mutable location, block and building selections with scoped keys and a general fallback. GetLocationVariant sets lastLocationKey, which later block/building lookups implicitly use. Interleaving location lookups can therefore change resolution context even on one thread. SetLocationVariant returns ContainsKey despite documenting true for a new selection, the opposite convention to SetBlockVariant for first insertion versus replacement. It also clears the RMB layout cache. Native SAVE writes WorldVariationData_v1 and attempts to restore it before RestorePositionHelper. Missing sidecar content skips restoration at that call site. A load exception logs and continues, so the actual state after missing data or failed restoration needs a cross-session test. Preserve restore-before-reconstruction and separate content definitions from saved selection. See Utility/AssetInjection/WorldDataVariants.cs, Utility/AssetInjection/WorldDataReplacement.cs and Game/Serialization/SaveLoadManager.cs.

## Comparison

| Concern | DFU | Proposed Godot design |
| --- | --- | --- |
| Content intake | Classic reader façade plus multiple loose and mod entry paths | Format adapters and per-domain lookup with explicit source policy and diagnostics |
| Definitions | Legacy IDs, mutable registries and owner-specific patch logic | Validated definitions, stable references and explicit legacy mapping |
| Localization | Engine tables, token converters and context-dependent macros | Stable keys, tested token conversion and explicit values for presentation |
| Runtime media and world variants | Unity resource caches and static variant selection | Media caches owned by AV and saved selections owned by the world session |

Verify resolution against same-basename files, conflicting mod packages, invalid patches and absent inputs. Test location/key fixtures and load sequential saves with missing, invalid and valid variant selections. Exercise localization fallback, duplicate rows, token round-trips, names and glyph coverage. Measure cold start and resource memory with representative archives and streamed scenes. No runtime checks or classic fixtures were exercised in this review.
