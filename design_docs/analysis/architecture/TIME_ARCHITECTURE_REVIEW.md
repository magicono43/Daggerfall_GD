# TIME architecture review

Covers TIME-001 through TIME-018 in the [feature catalog](../systems/TIME_FEATURE_CATALOG.md). Evidence is from the local DFU 1.1.1 Release snapshot. See the [repository overview](../00_REPOSITORY_OVERVIEW.md) for revision limits. Source paths are relative to Assets/Scripts. Findings describe static code behavior.

## Existing architecture

### Calendar, advancement and catch-up · TIME-001–004

Utility/DaggerfallDateTime.cs owns calendar arithmetic, classic minute conversion and the classic start date. Internal/WorldTime.cs advances that mutable calendar with scaled frame time and an optional requested advance, then calls RaiseEvents. Rest, travel and court also call RaiseTime directly. Keep calendar conversion independent of scene state and distinguish real time, scaled simulation time and calendar time.

RaiseEvents compares the last sampled hour/day/month/year to the current values. Dawn and related events require the final hour to equal the boundary hour. A jump landing past dawn can skip that notification, and a whole-day jump ending at the same hour can leave the hour comparison unchanged. This is a confirmed endpoint policy. It can be suitable for display refresh but does not enumerate every crossed boundary. Other consumers implement their own catch-up. EntityEffectBroker caps magic rounds, PlayerEntity walks elapsed minutes for political/legal work, Questing.Clock tracks sampled time and LoanChecker checks deadlines. The different strategies reflect different semantics, but callers must know which systems catch up immediately and which wait for a later update. Long-jump costs and event interactions are unmeasured.

### Weather, daylight and holidays · TIME-005–008, 018

Game/Weather/Weather.cs parses and compiles climate/season odds. Game/WeatherManager.cs selects weather and applies it to PlayerWeather, fog and sunlight. SetClimateWeathers generates weather for six groups. SetWeatherFromWeatherClimateArray uses TravelTimeCalculator.climateIndices to map the current climate to a group. This reuses a mapping but makes weather depend on a travel calculator. PlayerEntity requests climate updates after day changes and UpdateFromClimateArrayCheck defers application until GPS is ready. PollWeatherChanges exists, but its ordinary Update call is commented out in this snapshot. The respawn-complete handler can explicitly poll when climate changes. Preserve the distinction between choosing weather, applying a pending state and rendering it.

Game/SunlightManager.cs and PlayerEnterExit consume time and weather to update daylight and context. FormulaHelper.GetHolidayId feeds both holiday messages and service pricing. Calendar lookup is useful shared data. Keep display and pricing consumers separate so a weather or calendar UI refresh cannot reroll state or repeat a gameplay effect.

SaveLoadManager.RestoreDateTimeData restores time during load. WeatherManager.SaveLoadManager_OnLoad applies saved outdoor weather and then overrides fog for interior context. The classic path translates weather in StartGameBehaviour. This makes the distinction between weather and local presentation explicit, but readiness and callbacks can also select weather. Verify whether subsequent climate refresh preserves or replaces restored weather, especially across interior-to-exterior transitions. No complete continuity audit of climate arrays or random state was performed.

### Rest and loiter · TIME-009–011

Game/UserInterfaceWindows/DaggerfallRestWindow.cs handles eligibility, rental and bed context, finite rest, heal-until and loiter. CanRest and the GameManager veto surface provide policy seams. TickRest checks enemy interruption and vetoes before advancing. It waits while another window is on top, uses real-time pacing, raises calendar time in minute chunks and explicitly ticks QuestMachine. Hourly recovery and completion have separate paths, including practice checks and sleep notifications. Fine-grained steps let quests interrupt rest without waiting an entire hour. The window owns both presentation and the simulation loop, so alternate entry points must reproduce pause, stop and completion order. Test interruptions raised during a quest tick, stacked prompts and no-regeneration characters. Rest-related recovery ownership also appears in the [CHAR review](CHAR_ARCHITECTURE_REVIEW.md).

### Travel selection, quotation and arrival · TIME-012–017

DaggerfallTravelMapWindow handles map search, destination selection and disclosure. Game/Utility/TravelTimeCalculator.cs estimates route time and trip cost using travel options, transport and world context. It also reads GameManager for the origin and some guild pricing. Keeping the calculator separate from the map window is valuable. Explicit inputs would allow headless tests for endpoints, climate, mounts and ship constraints. TransportManager tracks horse/cart availability and ship transition context. DaggerfallBankManager resolves the owned ship and its coordinates. Preserve transport entitlement separately from current traversal mode.

DaggerfallTravelPopUp checks affordability and disease confirmation before setting a flag for later execution. performFastTravel deducts payment, publishes the pre-travel event, caches ship state if required, initiates teleport, applies cautious recovery and advances time. It adjusts daylight arrival for sunlight-sensitive characters and early/late cautious travel. It then raises skills and the post-travel event. DeductFastTravelGold ignores the remaining amount returned by DeductGoldAmount. If affordability changes before execution, the payment operation can leave a shortfall while travel proceeds. Ordinary reachability is unverified. Post-travel runs after teleport initiation without waiting for streamed placement. Treat that event as distinct from world arrival readiness. See [WORLD](WORLD_ARCHITECTURE_REVIEW.md) and [ECON](ECON_ARCHITECTURE_REVIEW.md) for related contracts.

## Comparison

| Concern | DFU | Proposed Godot design |
| --- | --- | --- |
| Time | Mutable calendar with endpoint events and consumer catch-up | Explicit clock advance, boundary policy and restore ordering |
| Weather | Climate selection and presentation coordinated in WeatherManager | Weather state owned by TIME and rendered by AV |
| Rest | UI drives paced time advances and completion | Rest session with explicit interruption and recovery outcomes |
| Travel | UI quotes, charges, teleports and advances time | Revalidated trip operation with distinct settlement and placement results |

Verify jumps across dawn and identical-hour endpoints, consumer order on long skips, weather restore and interior transitions, interrupted rest, quote changes, transport eligibility and arrival placement failure. Measure catch-up before changing iteration policies. No runtime, profiling or classic parity tests were performed.
