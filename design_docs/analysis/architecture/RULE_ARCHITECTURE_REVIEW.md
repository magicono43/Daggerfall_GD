# RULE architecture review

Scope covers RULE-001 through RULE-028 in the [feature catalog](../systems/RULE_FEATURE_CATALOG.md), using the local DFU 1.1.1 Release snapshot. Exact commit is unavailable in the [repository overview](../00_REPOSITORY_OVERVIEW.md). Source paths are relative to Assets/Scripts. Findings concern the inspected code. Runtime frequency, balance and classic equivalence require fixtures.

## Existing architecture

### Randomness and formula extension · RULE-001–004

Game/Utility/Dice100.cs wraps Unity's global Random.Range with explicit percentile boundaries. API/DFRandom.cs implements a separate classic generator with exposed seed, inclusive and exclusive modulo range helpers, and one static saved-state slot. The classic algorithm is small enough to port and check against known vectors. SaveSeed/RestoreSeed cannot nest independently because a second save replaces the first. Equal bounds in the two-argument exclusive helper produce modulo by zero. Preserve intentional legacy range mapping when compatibility matters.

Game/Formulas/FormulaHelper.cs uses both generators. BonusPool reseeds Unity random from Time.frameCount and CalculateHitPointsPerLevelUp reseeds DFRandom from Time.renderedFrameCount. RollMaxHealth invokes the latter repeatedly in a synchronous loop. With unchanged frame count and unchanged inputs, those iterations produce the same first draw. Game/Questing/QuestMachine.cs ParseQuest seeds Unity random from its own System.Random. Building naming also reseeds DFRandom. These are confirmed shared-state changes. Which unrelated rolls change during ordinary play depends on caller order. Persisted or replayable random sequences are a design choice for the new RPG. No comprehensive DFU save-state audit was performed.

FormulaHelper.RegisterOverride accepts a string key, Mod provider and generic delegate. A strictly higher LoadPriority replaces the current override. Equal priority retains the existing one. TryGetOverride casts to the caller's expected delegate type, logs and removes an incompatible override, then the formula uses its default. An incompatible higher-priority registration can therefore displace a valid prior override and leave the default active on first use. The registry provides a useful mod seam and attribution, but signature validation comes after conflict resolution. Each hooked formula pays a dictionary lookup. Actual cost is unmeasured.

### Character and interaction calculations · RULE-005–011

FormulaHelper groups derived attributes, growth, skill-to-level conversion and recovery. DamageModifier, SpellPoints, MaxEncumbrance and CalculatePlayerLevel expose useful parameter-driven entry points. CalculateHealthRecoveryRate and other recovery paths consume entity values or context. Keep rounding, bounds and permanent/live distinctions visible at the call site. Preserve integer arithmetic for rules where truncation is observable.

Interior/exterior lockpicking, pickpocketing, shoplifting, stealth and climbing share a calculation façade, but their inputs vary. CalculateInteriorLockpickingChance takes scalars while CalculateStealthChance accepts DaggerfallEntityBehaviour. The difference is useful evidence for extracting inputs at the owner boundary where calculations need entity state. MOVE, LOC, LAW and NPC still own action eligibility and consequences. Hardcoded constants are reasonable for stable formula semantics. Balance knobs and content-specific thresholds are candidates for validated data when authors actually need to edit them.

### Attack, resistance and spell rules · RULE-012–018

FormulaHelper.CalculateAttackDamage chooses attack route, including comparing an enemy's weapon and weaponless average damage. It delegates to hit/body-part and armor calculations, swing/proficiency/racial/backstab modifiers, timing and damage helpers. The smaller methods and adjustment hooks are useful seams. The top-level override returns immediately and bypasses the default pipeline, including its side effects.

Despite returning an integer, the default function can invoke monster-hit effects, apply and clear weapon poison, damage equipment, and invoke an enchantment callback before returning. WeaponManager and EnemyAttack then use the returned damage. The method is a resolver with side effects, so a preview, retry or override can omit or repeat consequences unless the caller knows the contract. Actual ordering matters because a callback may read state after an earlier mutation. See CalculateAttackDamage, DamageEquipment, OnMonsterHit, InflictPoison and InflictDisease.

SavingThrow reads resistance flags, live race and other target modifiers. Its return is a percentage interpreted by ModifyEffectAmount, with zero used for full resistance. Preserve the ordering of early resistance rolls and later scaling when matching behavior. Spell cost and capacity have reusable entry points, but they span effect templates, cast and enchantment settings, and entity context. CalculateTotalEffectCosts, CalculateEffectCosts, CalculateCastingCost and GetItemEnchantmentPower are places to preserve conversion and minimum-cost rules. A shared calculator can consume resolved data while MAGIC retains effect/template ownership. No throughput problem is established.

### Enemies, economy, items and generated content · RULE-019–028

- **Enemy and encounter rules (019–020).** FormulaHelper groups enemy language, weight, health, pacification and ambient spawn checks. These are useful common entry points for NPC and COMBAT. Selection and actual spawning belong to NPC/WORLD, while chance evaluation can accept explicit environment inputs and draws. Review encounter distributions and classic provenance before treating existing constants as authoritative.
- **Prices and services (021–024).** CalculateCost, CalculateTradePrice, repair/identify and service functions provide shared rules. ApplyRegionalPriceAdjustment reads live GPS and PlayerEntity.RegionData. UpdateRegionalPrices iterates region and elapsed steps, consumes percentile draws and changes regional condition flags via the player. This mixes quote arithmetic with economy state and political inputs. Performance scales with elapsed steps and regions, but no long catch-up profile is available. Loan, room, temple and summoning rules need boundary fixtures and clear owner inputs.
- **Items (025–026).** IsItemStackable treats a true mod result as additive permission and falls through to built-in rules for false. This differs from replacement hooks. ItemCollection owns the actual stack operation. RandomMaterial uses player level, Unity random and ItemBuilder.materialsByModifier. RandomArmorMaterial builds on the material path. Keep eligibility separate from stack equivalence and validate weight coverage for every reachable roll.
- **Names and regional mappings (027–028).** GenerateBuildingName combines a classic seed, building type, localized parts, faction data and the current region via globals. It includes an intentional extra draw for a macro and documents a deliberate divergence from classic naming. Keep draw order in compatibility fixtures. GetHolidayId and GetVampireClan contain region policy mappings that can move into authored content if expansion requires it. Stable building identity should remain separate from generated text.

The main source for these groups is Game/Formulas/FormulaHelper.cs, with Game/Items/ItemBuilder.cs, Game/Items/ItemCollection.cs and Utility/BuildingNames.cs as supporting owners or consumers.

## Comparison

| Concern | DFU | Proposed Godot design |
| --- | --- | --- |
| Randomness | Global Unity and classic generators with local reseeding call sites | Owned streams and explicit draws, with a classic compatibility generator where needed |
| Formulas and mods | One broad façade with string-keyed overrides | Domain calculators and a small set of validated, typed extension points |
| Attack and saving throws | Numeric results with context reads and attack-side mutations | Explicit inputs and ordered combat effects with documented result semantics |
| Prices and generated names | Global context plus owner records and shared random draws | Economy-owned state and reproducible naming context independent of display identity |

Verify classic vectors and range endpoints, growth rolls across repeated calls, nested seed use, override priority and malformed delegates. Exercise attack side-effect order, resistance percentages, stack semantics, material distributions, seeded names and long economy catch-up. Measure before optimizing. No runtime, replay or classic parity tests were performed.
