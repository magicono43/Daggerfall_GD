# MOD-008 — Visual and audio replacements

**Approved — finalized v1.** The user approved Draft v1 on 2026-11-18.

## Purpose and intended player experience

Players can install packs that replace presentation assets and inspect which pack supplied the result. Authors can target classic and supported mod-added assets through stable identifiers.

## Daggerfall Unity reference

DFU 1.1.1 resolves media replacements through separate helpers for models, textures and materials, sound and music, and movies. Examples include a classic model ID, texture archive/record/frame, and filenames for MIDI and movies. See [MeshReplacement.cs](../../../../reference_material/daggerfall-unity-1.1.1-cve-2025/Assets/Scripts/Utility/AssetInjection/MeshReplacement.cs#L99), [TextureReplacement.cs](../../../../reference_material/daggerfall-unity-1.1.1-cve-2025/Assets/Scripts/Utility/AssetInjection/TextureReplacement.cs#L154), [SoundReplacement.cs](../../../../reference_material/daggerfall-unity-1.1.1-cve-2025/Assets/Scripts/Utility/AssetInjection/SoundReplacement.cs#L69) and [VideoReplacement.cs](../../../../reference_material/daggerfall-unity-1.1.1-cve-2025/Assets/Scripts/Utility/AssetInjection/VideoReplacement.cs#L49).

## Confirmed rules

1. Authors explicitly map each target asset to a replacement file. Accept stable logical IDs, including supported mod-added targets, and supported classic identifiers. Resolve equivalent identifiers to the same domain-scoped logical identity. A coincidental filename match carries no replacement intent.
2. Resolve valid replacements under DATA-003 and the media owner's compatibility and context rules. Apply shipped defaults, enabled mods in resolved order, then supported loose overrides. Direct references to a provider's export continue to follow MOD-006.
3. Validate the selected replacement under the owning media contract. Keep visual-only replacements within approved placement, collision, interaction and gameplay constraints. Apply approved frame, timing, format and playback contracts where relevant.
4. With no selected replacement, use the owner's baseline resolution. An invalid selected replacement uses explicit DATA-003 recovery. A declared optional fallback or omission follows the owner's approved policy. Missing required assets or playback failures use the relevant owner recovery.
5. Show contributors and the winning replacement in pre-menu Content Diagnostics. Routine enablement is at package level for the initial release. Explicit omission of an invalid contribution remains available when approved recovery and revalidation permit it.

See MOD-008-D01 and D02 in the [gameplay decision log](../../GAMEPLAY_DECISIONS.md).

## Parameters, required data, inputs and outputs

Inputs include target domain and ID or classic alias, replacement file reference, source identity, candidate order, owner-required context and compatibility metadata. Outputs include a resolved asset reference and provenance, or actionable missing, invalid or unsupported diagnostics. Media owners define format, variant and playback parameters. No gameplay formulas or balance values apply here.

## Interactions and save/load

- [MOD-002](MOD-002.md) manages package enablement. [MOD-006](MOD-006.md) owns asset lookup and shared versus editable resources. [MOD-007](MOD-007.md) defines the pre-menu diagnostics view.
- [DATA-003](../DATA/DATA-003.md) governs precedence, recovery and the run-long configuration lock. [DATA-021](../DATA/DATA-021.md), [DATA-022](../DATA/DATA-022.md) and [DATA-023](../DATA/DATA-023.md) own media validation and mappings. AV and requesting gameplay owners govern instancing, playback and cue behavior.
- Save owners persist stable references and relevant instance state under their contracts. Resolved media and caches are reconstructed from the active plan. Gameplay-relevant references retain their existing compatibility checks.

## Edge cases and technical constraints

- Two mods may name the same target via a logical ID and a classic alias. Resolve them as competing contributions to one target.
- Reject ambiguous mappings or wrong-type files through content validation. An absent replacement and an invalid selected replacement have distinct outcomes.
- Cache identity accounts for the resolved source and result-changing context. Candidate rebuilds refresh the resolved winner and its diagnostics.

## Acceptance criteria

1. A classic alias and equivalent logical ID resolve to the same target. A supported mod-added logical asset can receive an explicit replacement.
2. Multiple valid replacements follow approved precedence and expose contributors and the winner in Content Diagnostics.
3. A visual-only replacement preserves the owner's gameplay contracts. A malformed selected replacement reports its source and reason through explicit recovery.
4. Disabling a package in pre-menu configuration changes the candidate replacements after rebuild. Entering the main menu locks the validated configuration.
