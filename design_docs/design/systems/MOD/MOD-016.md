# MOD-016 — Package and manifest authoring

**Approved — finalized v1.** The user approved Draft v1 on 2026-11-18.

## Purpose and intended experience

Authors can validate a mod project, test it unpacked and produce a distributable ZIP. A graphical tool supports interactive authoring, and a command-line tool supports repeatable releases. Both are initial-release targets subject to feasibility.

## Daggerfall Unity reference

DFU 1.1.1's Unity Editor tooling reads mod metadata and builds AssetBundles for selected platforms. A separate editor helper builds C# assemblies. See [CreateModEditorWindow.cs](../../../../reference_material/daggerfall-unity-1.1.1-cve-2025/Assets/Game/Addons/ModSupport/Editor/CreateModEditorWindow.cs#L615) and [ModAssemblyBuilder.cs](../../../../reference_material/daggerfall-unity-1.1.1-cve-2025/Assets/Game/Addons/ModSupport/Editor/ModAssemblyBuilder.cs#L29).

## Confirmed rules

1. Target graphical and command-line workflows with **Validate** and **Package** actions. Authors can also assemble a ZIP manually or use an unpacked package in the normal game. A package's eligibility follows the same rules whichever workflow produced it.
2. Reuse the game's package validation rules. Check root-level `mod.json`, required metadata, included files, path containment and declarations. Check dependencies, exports and content references where the supplied validation context allows. Report unresolved checks with their context. Verify the resulting ZIP against the packaged form of the contract.
3. Allow authors to explicitly include files from designated local workspace folders. Copy their contents into declared package-relative destinations. Diagnose missing source files and conflicting destinations. The distributed ZIP uses the installed-package containment rules and carries the included bytes.
4. Authors can use declared dependencies and explicit exports for assets intended to be installed once and used by multiple packages. The tool preserves those declarations. The authoring workflow respects MOD-004's script and trust rules and MOD-012's isolated quest testing.

See MOD-016-D01 and D02 in the [gameplay decision log](../../GAMEPLAY_DECISIONS.md).

## Parameters, data, inputs and outputs

Inputs include project files, the manifest, explicit workspace source and destination mappings, output location and any available dependency or target context. Outputs include validation diagnostics and a verified ZIP for successful packaging. There are no gameplay formulas or balance parameters. Exact command syntax, exit status conventions and GUI layout remain open.

## Interactions and save/load

- [MOD-001](MOD-001.md) defines discovery, package containment and exports. [MOD-003](MOD-003.md) defines dependency checks. [MOD-004](MOD-004.md) defines executable eligibility.
- [MOD-012](MOD-012.md) defines running-game quest tests. Packaging validation and runtime testing report different stages of readiness.
- Packaging preserves the author's declared stable identity and version. Save compatibility follows [MOD-015](MOD-015.md) and [SAVE-017](../SAVE/SAVE-017.md).

## Edge cases and technical constraints

- An external file can change or disappear between validation and packaging. Verify the actual packaged contents.
- Reject an unsafe destination or conflicting package path. Report the affected files.
- Static validation does not execute mod gameplay or grant approval for trusted code.
- Report a failed package build as a failure. Preserve source projects during validation and packaging.

## Acceptance criteria

1. Graphical and command-line workflows validate and package the same valid project under equivalent rules. The resulting ZIP is discoverable alongside an equivalent unpacked package.
2. Invalid metadata, missing files and conflicting destinations produce actionable diagnostics. A failed build cannot be reported as a valid release.
3. An explicitly included external workspace file is copied into the ZIP. The result loads on a machine without the author workspace. A declared shared asset dependency resolves through its installed provider.
