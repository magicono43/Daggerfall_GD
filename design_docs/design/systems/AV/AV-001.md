# AV-001 — Model and material presentation

**Approval status — Approved, finalized v1.** The user approved Draft v1 on 2026-11-16 with “I approve”. See AV-001-A01 in the [gameplay decision log](../../GAMEPLAY_DECISIONS.md#av-001-interview-decisions).

## Gameplay purpose and intended player experience

Render recognizable world geometry with readable silhouettes, aligned surfaces and context-appropriate materials. Players start with crisp classic textures and can select a smoother presentation with lighting-responsive surface detail where authored. Both stock presets preserve the placement and gameplay meaning of each object.

## Confirmed requirements

[AV-001-D01 through D04](../../GAMEPLAY_DECISIONS.md#av-001-interview-decisions) confirm the Classic default, live updates for supported context variants, a moddable Enhanced preset and diagnosed omission of explicitly optional decoration. AV-001-A01 approves the complete specification.

## Existing Daggerfall Unity behavior

In the local DFU 1.1.1 release snapshot, `Assets/Scripts/MeshReader.cs#GetMesh` constructs a Unity mesh with material assignments per submesh and retains the original texture keys. `MaterialReader.cs#GetMaterial` resolves archive, record and frame, reuses cached materials and can apply replacement textures or materials. `Internal/DaggerfallMesh.cs#SetClimate` rebuilds assignments from original texture keys. `MaterialReader.cs#ChangeClimate` applies climate and season archive swaps and changes window emission on the resulting material. That shared material write can couple instances that require different window styles. These are static findings. Rendered parity and performance remain unmeasured. See the [AV architecture review](../../../analysis/architecture/AV_ARCHITECTURE_REVIEW.md).

## Detailed rules and behaviors

1. Bind validated model geometry and surface mappings to the placement supplied by LOC/WORLD. Preserve the approved model scale, orientation, winding, normals, UVs, tiling, transparency and surface associations. Apply DATA-021/022 resource selection and replacement rules before building AV resources. Keep placement identity and instance state distinct from model and material identities.
2. **Classic** is the stock default and uses nearest-neighbor sampling, classic source imagery or its resolved replacement, and authored emission where applicable. **Enhanced** uses the same resolved geometry, color imagery and emission, with smoother filtering using appropriate mipmaps and compatible authored normal maps where supplied. Enhanced surfaces without an optional normal map still receive smoother filtering. Neither stock preset changes collision, interaction bounds, navigation, automap meaning or gameplay exposure.
3. Make presentation moddable at the data level. Mods can add or customize presets, filtering and optional map policies, model and surface assets, emission settings and supported context selectors, subject to DATA-003 precedence and DATA-021/022 validation. Both stock presets operate on resolved content. Whole-material replacements and any custom shader or executable provider follow their declared AV/MOD compatibility and registration contracts.
4. Evaluate climate, season, daylight and fog variants from the context for the particular placement. Define applicability and deterministic precedence in the supported profile so simultaneous changes resolve to one effective result. Publish valid updates to visible surfaces when their relevant context or selected preset changes. New instances use current context. Keep prior valid surfaces coherent while a runtime update prepares, and discard results for superseded context, placement or session. Required restoration uses the restored context before the view is revealed.
5. Share equivalent immutable resources and isolate per-instance inputs such as differing emission styles. Resource reuse includes resolved source, conversion, variant, frame where applicable, and effective presentation settings when they change output. Retire resources under AV ownership when their use and retention end. Rebinding visuals must preserve live door poses, interaction bindings and other owner state.
6. Missing required geometry or imagery fails affected preparation through the existing DATA and LOC/WORLD recovery paths. Invalid selected replacements follow explicit contribution recovery. If explicitly optional decoration is unavailable, apply a declared compatible fallback if supplied. Otherwise allow omission, diagnose the affected asset and placement, and let the rest of the eligible area proceed. The owner determines optionality. A surface required for gameplay readability or an object required for an interaction cannot become optional through preset selection.

## Parameters, configuration and required data

- Stable model, placement, material and preset IDs, resolved asset provenance, transforms, surface assignments, UV/tiling data and declared requiredness.
- Validated context selectors and precedence, supported texture sampling and mip policy, opacity settings, optional map roles and compatibility, and authored emission color and intensity. Exact filtering parameters, transition curves and tolerances remain open. Daylight and seasonal calculations come from their owners.
- Player preset selection and the resolved preset registry. Save the selection as a graphics preference. If a saved mod-defined preset is unavailable, report it and use the validated stock Classic preset. Apply the separate content recovery rules to an invalid selected replacement.

## Inputs, outputs and events

- **Inputs** include validated placement and resource requests, committed context updates, preset selection and area activation or retirement.
- **Outputs** include the mesh and surface bindings, effective variant and preset, and attributable preparation or omission diagnostics.
- **Events** report presentation readiness, failure or retirement for the applicable placement/activation. Rendering results do not publish time advancement, gameplay readiness, traversal, discovery or interaction.

## Edge cases and failure conditions

- Resolve conflicting variant rules through validated precedence. Reject ambiguous or incompatible selected definitions through the applicable content recovery.
- Reapply context and preset selection as one coherent surface assignment when rapid updates coincide. Stale work from an unloaded area or older setting cannot overwrite the current binding.
- Test very oblique repeating surfaces, cutout edges with mipmaps, mismatched or absent maps, and differently styled windows that share source imagery. Suppress repeated diagnostics for the same unresolved omission during one activation.

## Save/load considerations

Rebuild render resources and current variants from resolved content, the active graphics preference and restored world context. Preserve object state in its gameplay owner. Restore across a time boundary with the variant for the saved instant and zero elapsed time. Follow the existing migration and compatibility rules for content changes that affect saved identity or gameplay state.

## Technical constraints

Target Godot 4.7.2. Keep DATA decoding, AV render resources and LOC/WORLD placement responsibilities distinct. Validate conversion and visual behavior with representative stock and mod assets. Cache scope and batching must preserve independent variants and instance state. Choose filtering costs and resource budgets using representative performance measurements.

## Acceptance criteria

1. On default settings, a representative classic building has the expected scale, placement, surfaces and crisp sampling. A registered replacement preserves the validated placement and gameplay contracts.
2. Switching between Classic, Enhanced and an added valid mod preset updates loaded surfaces. Enhanced reduces distant texture shimmer on the fixture and shows lighting-responsive detail where a compatible normal map is supplied. A surface without that optional map still renders.
3. A supported season or window-style transition updates the visible affected materials. Two simultaneous window styles remain independent. Rapid context and preset changes leave the latest effective view coherent.
4. A missing explicitly optional decoration follows its declared fallback or is omitted with an attributable diagnostic. Missing required resources fail preparation. An invalid selected replacement triggers explicit recovery.
5. Switching presets and rebuilding materials preserve placement identity, open door state, collision, interaction points, automap meaning and gameplay exposure. Native load reveals the restored visual context without replaying time or gameplay events.
