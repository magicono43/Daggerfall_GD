# AV-011 — Context-driven music selection

**Approval status — Approved, finalized v1.** The user approved Draft v1 on 2026-11-17 with “I approve”. See AV-011-A01 in the [gameplay decision log](../../GAMEPLAY_DECISIONS.md#av-011-interview-decisions).

## Gameplay purpose and intended player experience

Give recognizable music to outdoor weather and time, taverns, dungeons, courts and other distinct settings. Keep music continuous during ordinary outdoor exploration and retain the classic way of choosing a track within a playlist.

## Confirmed requirements

[AV-011-D01 and D02](../../GAMEPLAY_DECISIONS.md#av-011-interview-decisions) confirm the classic baseline, prompt setting transitions, deferred outdoor transitions and moddable DFU-style selection. AV-011-A01 approves the complete specification.

## Existing Daggerfall Unity behavior

In the local DFU 1.1.1 release snapshot, `Assets/Scripts/Game/SongManager.cs#AssignPlaylist` prioritizes arrest for court music, then selects by environment and, outdoors, by daylight and weather. `UpdateSong` can request another track when the playlist, day or location changes. `SelectCurrentSong` uses daily tavern rotation, seeded dungeon and daily choices, and random guild selection. The source uses shared random generators. `PlayCurrentSong` skips restarting the same song while it is playing. These findings are from static inspection.

## Detailed rules and behaviors

1. Resolve the stock context playlist from committed player context. Use classic track pools and ordered context mappings, including court music while the applicable arrest context is active. Outdoor daytime playlists follow the effective weather grouping, and outdoor nights use the night playlist. Use the applicable indoor or special-area mapping when eligible. A validated mod can add or override mappings, precedence, pools and selection policies.
2. Crossfade promptly on entry to a distinct musical setting, such as a tavern, dungeon or court, once the selected track is ready. Apply the same transition policy when leaving that setting for a different one. For ordinary outdoor weather and day/night changes, let the active track finish. Then select using the latest eligible committed context. Midnight and location changes with the same effective playlist preserve the current track. If a transition resolves to the same track already playing, continue playback.
3. Keep switch timing distinct from track selection. A day or location change can update inputs for the next choice without forcing a restart. For the stock pools, select using DFU's per-playlist rules and the context at the selection boundary. A repeat is valid if the stock rule selects the same song again. Support validated mod alternatives such as shuffle, fixed themes and context-specific transitions.
4. Reproduce the stock seeded selections with scoped presentation draws. Keep gameplay random state independent. Playlists with equivalent selections retain their declared order. Evaluate random stock guild choices on admitted selection boundaries, without rerolling on failed playback retries or redundant notifications.
5. Key pending playback to the current session, context and selection. Discard stale work and retarget interrupted fades from the current audible mix. A deferred outdoor request replaced before the track ends never starts as an intermediate song. When a track finishes and music is eligible, select from current context so a deferred change still has a boundary even for a track that would otherwise loop. Backend playback and replacement handling belong to AV-012.
6. Use DATA-023 recovery for invalid selected replacements and missing required media. For unavailable optional music, keep a usable eligible track playing. When no usable eligible track is playing, use a declared compatible fallback or diagnosed silence. Bound retries and preserve authoritative world and legal state. Music selection follows the active scope and preference gates.

## Formulas, parameters and configuration

For a validated nonempty stock pool with length `N` and classic-compatible game-day index `D`:

- Tavern index is `D mod N`.
- Dungeon interior index is the first compatible DFU random result from seed `classicDungeonField XOR (classicRegionByte << 8)`, reduced modulo `N`. The field is `Dungeon.RecordElement.Header.Unknown2`. The source defaults both seed inputs to zero when no current location is available.
- Other multi-track stock pools use the first compatible DFU random result seeded with `D`, reduced modulo `N`, except for Mages Guild and the reference's unused sneaking branch, which select randomly. Single-track pools select index zero.

Validate playlist references and ordered tracks, day and dungeon selectors, switch policy, blend intervals and optional fallback scope. Native or mod locations without classic dungeon metadata require an explicit compatible selector or alternate profile. Numeric fades and exact boundary behavior need fixtures.

## Required data

Committed location, special-area, arrest, weather and daylight context, classic-compatible day and dungeon inputs where applicable, resolved playlist and policy identities and provenance, current and pending track requests, playback lifecycle and active music preferences.

## Inputs, outputs and events

- **Inputs** include committed context changes, activation and playback completion or failure, music preferences and resolved content.
- **Outputs** include effective playlist, admitted logical track, transition requests and diagnostics.
- **Events** report selection and playback handoff outcomes. Music cues do not alter gameplay time, court flow, location membership or weather.

## Cross-system review

- **TIME-001/006/007/018** govern day, effective weather, daylight and restored destination state. Music uses committed context and does not replay historical changes.
- **LOC-012, WORLD and LAW** govern special areas, placement and legal context. Court music follows an applicable committed state.
- **DATA-003/023, MOD and RULE-003** govern validated media and policies, provenance and random separation. **AV-009/010** own clips and ambience. **AV-012** will govern music playback and replacements.

The specification follows the reviewed context, media and random ownership boundaries.

## Edge cases and failure conditions

- Test simultaneous day, weather and location changes, rapid returns across a doorway and a court request during a fade. An obsolete selection or playback completion cannot supersede the latest context.
- Test missing or empty pools, unsupported media, same-track transitions and repeated callbacks after failure. Use explicit recovery and bound retries.
- Verify classic ordered pools and day, dungeon and guild selectors against fixtures. Ensure music selection cannot perturb gameplay randomness.

## Save/load considerations

Persist music preferences separately from game saves. Rebuild musical selection from the restored context. Exact track position and active fades are transient. Skip historical transitions after restore or fast travel.

## Technical constraints

Target Godot 4.7.2. Keep selection independent of recorded audio or MIDI backend. Require a usable track boundary from the backend for deferred switches and scope fades to current playback. Verify playback and crossfade support across the backends defined in AV-012.

## Acceptance criteria

1. Classic context and ordered track pools produce expected results for verified day, location and court fixtures. Music leaves gameplay random state unaffected.
2. A new musical setting crossfades promptly. Outdoor weather and day/night changes use the latest eligible playlist when the current track ends. Midnight and same-playlist location changes preserve playback.
3. Tavern, dungeon and daily selection reproduce verified stock choices at an admitted selection boundary. Guild selection uses isolated presentation randomness. A validated mod can replace playlists and choose different switch and selection policies.
4. Repeated or stale requests do not restart the same current track or start obsolete transitions. Optional playback failure retains an eligible track, uses declared fallback or yields diagnosed silence.
5. Native restore selects from restored context without replaying prior musical transitions.
