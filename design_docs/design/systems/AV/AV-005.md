# AV-005 — Retro resolution and HUD composition

**Approval status — Approved, finalized v1.** The user approved Draft v1 on 2026-11-17 with “I approve”. See AV-005-A01 in the [gameplay decision log](../../GAMEPLAY_DECISIONS.md#av-005-interview-decisions).

## Gameplay purpose and intended player experience

Let players choose a pixelated world and optionally a pixelated gameplay HUD. Menus remain readable at display resolution with independently adjustable UI size. The retro frame fits within the available display area and preserves the selected framing.

## Confirmed requirements

[AV-005-D01 and D02](../../GAMEPLAY_DECISIONS.md#av-005-interview-decisions) confirm stock modes, independent gameplay HUD pixelation, native-resolution menus, framing and scaling preferences, and moddable presets. AV-005-A01 approves the complete specification.

## Existing Daggerfall Unity behavior

In the local DFU 1.1.1 release snapshot, `Assets/Scripts/Utility/RetroRenderer.cs#UpdateRenderTarget` selects Off, 320×200 or 640×400 and uses separate targets for the docked large HUD. `Utility/RetroPresentation.cs#OnRenderImage` blits the retro presentation source to the viewport. `Game/UserInterfaceWindows/RetroModeConfigPage.cs` exposes Off, 4:3 and 16:10 aspect correction. Findings are from static inspection. See the [AV architecture review](../../../analysis/architecture/AV_ARCHITECTURE_REVIEW.md).

## Detailed rules and behaviors

1. Default to **Off**, using display-resolution world and HUD presentation. Offer stock **320×200** and **640×400** world targets. The default retro composition pixelates the world. A separate gameplay HUD option includes the gameplay HUD in retro sampling when enabled. Menus, settings screens and their controls remain in the display-resolution UI pass in every mode.
2. Preserve the effective HUD layout contract in both overlay and docked layouts. A docked HUD reserves its layout space. A HUD overlay leaves the world frame available beneath it. Keep HUD sizing independent of world resolution and preserve valid control access under UI-004. Apply UI art aspect preservation independently of the world frame's pixel aspect correction.
3. Default retro output to **4:3** framing and offer **16:10**, which is square-pixel for the stock source targets. Center the selected frame within its available destination area and fit it without cropping. Use nearest-neighbor sampling for the final retro pass. AV-001 material sampling still applies inside the world render.
4. Offer integer scaling. For stock 16:10, select the largest fitting whole-number scale of the source raster. For aspect-corrected 4:3, retain the selected aspect and use whole-number multipliers of an aspect-corrected raster when one fits. Aspect correction can make source pixel steps uneven in this mode. If the selected integer mode cannot fit at its minimum scale, use nearest-neighbor fit and show the effective scaling mode. Apply equivalent validated rules to mod presets.
5. Apply mode, HUD, framing, resize and UI layout changes as a coherent update. Keep world and sky targets aligned. Use the same published geometry for drawing, clipping, hit tests and pointer transforms. Ignore world pointer input outside the applicable frame, while keeping valid UI controls in their layout regions interactive. Preserve valid focus and capture through the applicable UI/input owner. A display change produces no control activation or gameplay event.
6. Allow validated mods to add named resolution and framing presets under DATA-003. Declare stable IDs, dimensions, display aspect and integer-scaling compatibility. Validate bounds and resource support before activation. If a presentation request fails at runtime, retain the last usable mode and report the failure. If none is usable at startup, use Off where available. An unavailable saved mod preset follows the same preference recovery and leaves required content recovery to its existing owner.

## Formulas, parameters and configuration

For destination space `W × H` and selected display aspect `a > 0`, the ideal fit is `w = min(W, H × a)`, `h = w / a`. Align the output to display pixels within the available area. For square-pixel integer output with source `Sw × Sh`, use `k = floor(min(W / Sw, H / Sh))` when `k ≥ 1`. For corrected output, apply the same computation to the validated corrected raster. Exact raster rounding, minimum sizes and render budgets require fixtures.

## Required data

Display and available layout rectangles, active UI scale and HUD layout, resolved preset IDs and source dimensions, framing and scaling policies, supported render capabilities, effective viewport rectangles and coordinate transforms, and resolved mod provenance.

## Inputs, outputs and events

- **Inputs** include graphics preferences, display and viewport changes, HUD and UI layout, and resolved preset registry.
- **Outputs** include world and optional HUD render targets, final content rectangles, transforms for input mapping, and effective setting and diagnostic information.
- **Events** communicate applied or failed display configuration and updated geometry to interested presentation and UI owners.

## Cross-system review

- **UI-004** requires separate UI sizing, preserved artwork proportions, and matching rendering and pointer geometry. UI layer ownership and input handoffs remain with UI and CORE.
- **AV-001/002** govern material and sprite sampling within the world pass. **AV-003/004** supply the sky and atmosphere for the same view. **AV-006** will govern palette, depth and post-processing settings.
- **DATA-003** governs validated mod contributions and precedence. Graphics preferences are separate from a game save's content compatibility.

The specification follows the reviewed UI sizing, artwork and input ownership rules.

## Edge cases and failure conditions

- Test small windows, ultrawide displays, portrait layouts, and HUD toggles during resize. Bars and unused space must not offset pointer mapping.
- Verify removed presets, unsupported target dimensions and target allocation failure during live switching. Discard superseded work and retire replaced targets after coherent publication.
- Check 4:3 correction alongside independent UI scaling and HUD pixelation. Keep readable menus and valid focus throughout.

## Save/load considerations

Persist the selected mode, preset, framing, scaling and HUD pixelation as graphics preferences. Rebuild effective targets and layout from the current display and available presets. Native game load uses the active preferences and reconstructs view resources through the applicable readiness policy.

## Technical constraints

Target Godot 4.7.2. Keep world resolution, HUD composition and display-resolution UI independently configurable. Validate resource lifetime and consistent coordinate mapping across live changes. Measure target allocation, resize and composition costs before setting preset limits.

## Acceptance criteria

1. A fresh profile starts in Off. Both stock retro resolutions pixelate the world. Toggling HUD pixelation changes the gameplay HUD while menus remain display-resolution and UI sizing works independently.
2. Stock 4:3 and 16:10 frames fit without cropping. At supported integer sizes the square-pixel frame has even pixel steps. An undersized window uses the visible effective fallback without losing the frame.
3. Switching modes and resizing with an overlay or docked HUD keeps world/sky alignment, valid focus and matching hit regions. Pointer input in unused world space produces no world action.
4. Valid mod presets appear as choices. An unavailable or failed preference uses the documented recovery and reports the effective mode.
5. Native save/load leaves graphics preferences in their own scope and rebuilds a coherent view from the active display configuration.
