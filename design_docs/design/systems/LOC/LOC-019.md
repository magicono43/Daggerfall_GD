# LOC-019 — Notes and teleporter markers

**Approval status — Approved, finalized v1.** The user approved Draft v1 on 2026-11-14 with “I approve”.

## Gameplay purpose and intended player experience

Let players annotate explored dungeon and building interiors and recall the direction of teleport routes they have actually used. Keep notes recoverable after map eviction and keep undisclosed rooms hidden.

## Confirmed requirements

- **LOC-019-D01.** Allow notes on discovered geometry in dungeon and building-interior automaps. Anchor notes to stable segments and local positions. Preserve text and hide the pin when an incompatible edit leaves the anchor unresolved.
- **LOC-019-D02.** Learn a directed connection only after successful travel through the authored teleporter. Show connections on demand and reveal endpoints only where their map locations are disclosed.
- **LOC-019-D03.** Preserve compatible connections across reentry and save/load while the dungeon is remembered. Evict learned connections with dungeon geometry. Relearn them through successful use. Player notes retain their separate LOC-018 treatment.

See the [gameplay decision log](../../GAMEPLAY_DECISIONS.md#loc-019-interview-decisions).

## Existing Daggerfall Unity behavior

Static inspection of DFU 1.1.1. `Assets/Scripts/Game/Automap.cs#TryToAddOrEditUserNoteMarkerOnDungeonSegmentAtScreenPosition` and the corresponding remove method operate on dungeon map hits. `OnTeleportAction` records paired endpoint transforms from the action event, and the hover path displays the connection. `SaveStateAutomapDungeon` stores notes and learned connections in the same dungeon memory record. `Internal/DaggerfallAction.cs#Teleport` raises the source event before assigning the player's transform.

## Detailed rules and behaviors

1. Add, edit and remove notes through the map interface. Resolve a new pin against the selected discovered segment in the active layout. Keep a stable note ID, scoped segment reference, local position and text. Validate compatibility independently of identity after a layout edit. Use a validated mapping when available. Preserve text for unresolved anchors and hide those pins.
2. Record a directed source-to-destination connection from the committed teleport outcome under LOC-016 and WORLD-003. Bind it to the authored route and validated endpoints. Repeated traversal of the same directed connection retains one learned record. A failed or cancelled attempt, or an unrelated teleport landing at the same point, grants no route discovery. Learn reverse travel through its own successful traversal.
3. Present the connection on demand under LOC-018 disclosure. Show an endpoint only if its location is disclosed. A link line or destination label cannot disclose a hidden endpoint. Annotating the map grants no geometry discovery or traversal authority.
4. Apply LOC-018 retention. Stock reentry retains compatible learned routes within remembered dungeons. Eviction removes the learned routes associated with the evicted dungeon map. Keep player notes and hide pins in forgotten geometry until the location is rediscovered. Quest marks follow their own disclosure and retention rules.

## Formulas, parameters and configuration

LOC-018 owns map memory and carryover configuration. Note text limits, pin placement tolerances and connection styling remain open. No gameplay formula is introduced.

## Required data

Character, map scope, segment and note IDs, text, local anchor and layout version, directed route and endpoint references, committed traversal outcome, disclosure state and dungeon retention context.

## Inputs, outputs and events

- **Inputs** — Note editing intent, validated map hit, resolved layout, committed authored teleport outcome, disclosure state and eviction result.
- **Outputs** — Stored or updated notes, eligible pins and directed links, and explicit unresolved binding or unavailable outcomes.
- **Events** — Refresh annotations after note changes, committed route learning, disclosure or eviction. Annotation changes create no gameplay or quest outcome.

## Cross-system interactions

LOC-005/009 provide resolved layouts. LOC-018 supplies disclosure and retention. LOC-016 and WORLD-003 provide committed teleport outcomes. UI and AV present and edit annotations. QUEST owns independent quest marks. DATA, MOD and SAVE govern compatibility and restoration.

## Edge cases and failure conditions

- Check notes on stacked floors and moved or removed segments. Preserve text and hide unresolved pins.
- Check failed, repeated and reverse teleports and a route with a hidden endpoint. Disclosure and direction remain accurate.
- Check a changed route under an unchanged ID. Require validated compatibility before showing an old connection.
- Check eviction with player notes and learned connections. Retain the notes and forget the links.

## Save/load considerations

Persist committed notes independently of evictable dungeon memory. Save learned directed routes with their remembered dungeon and validate their endpoint bindings on restore. Restore annotation state without replaying traversal or granting discovery. Unresolved notes remain hidden pending a compatible mapping.

## Technical constraints

Target Godot 4.7.2. Keep annotations independent of live scene handles and use the active map layout when resolving positions. UI interaction, anchor format and link rendering remain open.

## Acceptance criteria

1. Players can add, edit and remove notes on discovered geometry in both map types. Compatible edits retain location and unresolved anchors preserve text with no visible pin.
2. Successful authored teleport learns one directed link. Failed attempts and reloads grant no new link. On-demand presentation respects endpoint disclosure.
3. Compatible links survive reentry and native load while remembered. Dungeon eviction forgets links and keeps notes. Rediscovery reveals compatible notes and successful use relearns links.
