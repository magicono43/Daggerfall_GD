# LOC-010 — Dungeon textures and story variants

**Approval status — Approved, finalized v1.** The user approved Draft v1 on 2026-11-14 with “I approve”.

## Gameplay purpose and intended player experience

Preserve recognizable classic and story locations. Players who enable variation can see ordinary dungeons reflect their region while retaining a consistent appearance on return.

## Confirmed requirements

- **LOC-010-D01.** Use verified classic palettes as the baseline for imported dungeons. Allow authored fixed story palettes that general variation respects. A validated site-specific override may deliberately change a fixed palette.
- **LOC-010-D02.** Offer opt-in variation for eligible sites using validated palettes, the dungeon's own climate and a stable dungeon-specific seed. Preserve the result across revisits and reloads under the same configuration. Isolate visual selection from gameplay randomness.
- **LOC-010-D03.** Support whole-palette overrides and explicit per-slot substitutions. Unspecified slots inherit from the resolved baseline. Invalid selected overrides or missing required assets follow DATA-022 recovery.

See the [gameplay decision log](../../GAMEPLAY_DECISIONS.md#loc-010-interview-decisions).

## Existing Daggerfall Unity behavior

Static inspection of DFU 1.1.1. `Assets/Scripts/Internal/DaggerfallDungeon.cs#ResetDungeonTextureTable` restores a six-slot default. `UseLocationDungeonTextureTable` selects classic, climate-based or alternate seeded tables depending on settings and story-site classification. Two modes bypass the story preference. `RandomiseDungeonTextureTable` separately draws a seed for the alternate algorithm. `DungeonTextureTables#RandomTextureTableClassic` reads the current player GPS climate and uses a provided seed. Its climate and archive mappings require fixture verification.

## Detailed rules and behaviors

1. Resolve the base palette for the dungeon by stable site identity and validated content. Imported sites use their verified classic palette. Respect an authored fixed palette when evaluating general variation.
2. When the player enables variation, resolve eligible sites using the destination dungeon's validated climate and a stable seed specific to that dungeon. Use an isolated presentation source and stable selection inputs so visit order, save/load and unrelated draws cannot change the result under the same configuration.
3. Resolve the site's explicit validated overrides against the selected baseline. A whole-palette override supplies the complete palette. A slot substitution supplies the declared slots and inherits the others from the resolved baseline. Apply the applicable DATA-003 precedence and DATA-022 replacement rules. A deliberate validated site override can change a fixed palette.
4. Validate required slot bindings and assets before the affected preparation is usable. Report a selected invalid contribution or missing required asset through approved content and consumer recovery. Use an optional fallback only where the owning asset policy explicitly supports it.
5. Bind the effective palette to the resolved dungeon presentation. Preserve authoritative geometry, collision, records, links and gameplay state through visual selection. Shared material resources must preserve instance isolation under DATA-022.

## Formulas, parameters and configuration

The DFU reference default archive table is `[119, 120, 122, 123, 124, 168]`. Configure fixed site palettes, eligible variation, climate-to-palette mappings and explicit overrides through validated content. The exact seed derivation, supported material slots and palette selection weights remain open. No gameplay formula is introduced.

## Required data

Stable dungeon and palette IDs, destination climate, supported material slots and requiredness, classic mappings, fixed and variation eligibility, seed or equivalent deterministic inputs, active configuration, effective override provenance and resolved asset bindings.

## Inputs, outputs and events

- **Inputs** — Dungeon identity and climate, active content and configuration, variation preference, and validated palette definitions and overrides.
- **Outputs** — Effective palette and scoped material bindings with provenance, or explicit failure for required invalid data.
- **Events** — Report required binding failures through DATA and the dungeon preparation owner. Palette selection creates no gameplay outcome.

## Cross-system interactions

- **LOC-009** consumes validated material bindings for the resolved dungeon layout.
- **DATA-003/006/022 and MOD** supply configuration, climate, asset validation and recovery. **AV** applies the resolved presentation.
- **RULE-003** governs isolation from gameplay randomness. **SAVE** uses restored site identity and compatible configuration to reconstruct presentation.

## Edge cases and failure conditions

- Check fixed sites with variation enabled and a deliberate site override.
- Check entry from different climates and different visit orders. Variation uses the dungeon's own climate.
- Check partial slot overrides, missing required assets, and invalid selected overrides. Preserve explicit failure and approved recovery.
- Check two instances sharing assets and a changed content configuration. Verify isolation and current binding validity.

## Save/load considerations

Reconstruct the effective palette from stable site identity and compatible deterministic configuration inputs. Retain any required selection inputs through their owners so unchanged configuration reproduces the result. Resolve changed configuration through approved content and compatibility rules. Restoring presentation leaves durable gameplay state under its owners.

## Technical constraints

Target Godot 4.7.2. Resolve assets against the active layout and validated content version. Include relevant variant and source inputs in resource cache identity. Resource representation and binding timing remain open.

## Acceptance criteria

1. Representative imported dungeons retain verified classic palettes by default. General variation respects authored fixed sites, and a validated site override can deliberately change one.
2. Opt-in variation yields the same palette for a dungeon across visit order and reload under the same configuration. Its climate and isolated visual selection do not affect gameplay draws.
3. Whole-palette and slot overrides resolve as authored. Unspecified slots inherit the resolved baseline. Required invalid assets enter approved recovery.
4. Effective material changes leave dungeon collision, links and durable gameplay state coherent. Shared assets do not leak instance changes.
