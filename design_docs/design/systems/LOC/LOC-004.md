# LOC-004 — City gates and exterior arrival markers

**Approval status — Approved, finalized v1.** The user approved Draft v1 on 2026-11-14 with “I approve”.

## Gameplay purpose and intended player experience

Make settlement gates follow predictable hours and give travel routes coherent arrival points. Players caught in a gate opening at closing time can clear it safely. An eligible after-hours route may arrive outside the walls at an authored approach.

## Confirmed requirements

- **LOC-004-D01.** Classic scheduled gates default to open from 06:00 until 18:00 game time. Support moddable per-gate schedules and authored always-open and always-closed gates. Resolve scheduled state from current game time after streaming, loading or a time skip.
- **LOC-004-D02.** Defer physical closure while an actor occupies the opening. Close once the opening clears if closure is still due. Apply scheduled access restrictions at closing time to routes that require gate access.
- **LOC-004-D03.** Give exterior arrival markers stable settlement-scoped IDs, explicit roles and gate dependencies. A general route that requires gate access can use an eligible authored outside approach as a default or backup. Recheck gate access and placement before commitment. Report failure when every authored candidate is unavailable.

See the [gameplay decision log](../../GAMEPLAY_DECISIONS.md#loc-004-interview-decisions).

## Existing Daggerfall Unity behavior

Static inspection of the local DFU 1.1.1 snapshot. `Assets/Scripts/Utility/RMBLayout.cs#IsCityGate` recognizes models 446 and 447. `Internal/DaggerfallCityGate.cs#Update` applies the current night state by swapping models through `SetOpen`. `Utility/DaggerfallDateTime.cs#IsNight` defines night as before 06:00 or at or after 18:00. `Internal/DaggerfallLocation.cs#EnumerateStartMarkers` collects editor start markers. `Terrain/StreamingWorld.cs#PositionPlayerToLocation` computes an approach-side position and can choose the nearest start marker to it. If no marker is selected, placement uses the calculated position.

## Detailed rules and behaviors

1. Resolve each authored gate's desired state from the current game clock and its configured schedule or fixed state. Update it across ordinary time advancement and time skips. Reconstruct it before publishing usable gate and route data on load or activation.
2. At closing time, publish restricted scheduled access to routes that depend on gate access. Keep physical passage open while the opening is occupied. Recheck occupancy before blocking passage and apply the current desired state if time changes again. Physical presentation, collision and applicable navigation must agree when passage becomes blocked or reopens. During deferred closure an actor can still pass physically. Any legal consequences follow LAW rules.
3. Resolve markers by settlement and stable marker ID. A marker declares its role, pose, and applicable gate dependencies. For general arrival, WORLD-003 applies the route's authored default, optional approach selection and ordered backups. An outside approach can be eligible at closing time if the route authorizes arrival there and the marker does not require passing through the closed gate. An outside arrival establishes presence from its actual committed pose under WORLD-013.
4. For a specific target, retain the target and apply only permitted local corrections. For a general route, try only eligible authored candidates within the designated destination under its route policy. Revalidate gate access, readiness and placement before commitment. Route-dependent gate access follows the scheduled state even while the gate remains physically open during deferred closure. An inaccessible target or exhausted candidate list produces an explicit failure through WORLD-003.

## Formulas, parameters and configuration

The classic default open interval is 06:00 inclusive to 18:00 exclusive in game time. Validate authored schedules and fixed states per gate. Routes configure marker roles, defaults, permitted approach selection and backup order under WORLD-003. Occupancy volumes, supported schedule exceptions and approach metrics remain open.

## Required data

Stable settlement, gate and marker references, active layout and provenance, gate schedule or fixed state, passage geometry and occupancy context, current game time, marker pose and role, applicable gate dependencies and route policy.

## Inputs, outputs and events

- **Inputs** — Validated layout and route definitions, game time, live occupancy and readiness, arrival intent and placement results.
- **Outputs** — Scheduled access state, physical passage state, eligible marker data and explicit unavailable results.
- **Events** — Distinguish scheduled access changes from physical passage changes. WORLD-003 publishes committed arrival outcomes.

## Cross-system interactions

- **TIME** supplies authoritative game time. **LOC-001 and WORLD-004/006** supply placement, collision and activation readiness. **DATA-003/005 and MOD** validate classic and authored records.
- **WORLD-003 and MOVE-027** own route arrival, correction and placement commitment. **WORLD-013** derives settlement presence. **LAW** owns enforcement and consequences.
- **AV and navigation consumers** use the live physical passage state. Route owners apply scheduled access dependencies.

## Edge cases and failure conditions

- Check the exact opening and closing boundaries and time skips that cross either boundary or both.
- If a reopening occurs during deferred closure, reconcile with the new desired state. If an actor enters during closure preparation, confirm clearance before applying blocking collision.
- Check a gate that closes during streamed arrival, an outside marker with blocked placement and a backup that depends on a closed gate. Exhausted candidates fail explicitly.
- Invalid required references or unavailable geometry use the applicable DATA and WORLD recovery. Obsolete activation and route work cannot publish current state.

## Save/load considerations

Recompute scheduled state from restored game time and validated gate definitions. Resolve physical passage against restored occupancy before exposing the affected area as usable. Restore committed pose and context through WORLD and SAVE. Validate durable marker or gate references against active content and use approved migration or recovery for required incompatibilities. Loading does not replay travel or settlement entry.

## Technical constraints

Target Godot 4.7.2. Keep scheduled access and physical passage independently queryable and coherent with the current layout and activation. Validate marker location and gate references in their authored context. Physical animation, occupancy detection and indexing remain open.

## Acceptance criteria

1. A classic scheduled gate opens at 06:00 and closes at 18:00 when clear. A custom schedule and each fixed state resolve correctly after a time skip, load or activation.
2. An occupied gate opening stays physically clear at closing time while dependent route access is restricted. The gate closes safely after clearance if closure is still due.
3. General arrival uses an eligible authored outside approach when allowed, with final gate and pose validation. A named target retains its identity, and a route with no usable candidate explicitly fails.
4. A restored or reactivated area exposes gate and marker data consistent with current time, occupancy and layout. It emits no duplicate arrival or entry outcomes.
