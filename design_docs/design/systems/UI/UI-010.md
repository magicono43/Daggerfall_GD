# UI-010 — Save selection and legacy load entry

**Approval status — Approved, finalized v1.** The user approved Draft v1 on 2026-11-16 with “I approve”. Updated 2026-11-16.

## Gameplay purpose and intended experience

Find the intended character and save, preview it, and deliberately create, overwrite or load a slot. Keep the player oriented after cancellation or a failed attempt.

## Confirmed requirements

- **UI-010-D01.** Group native saves by character and sort newest first within each group. In-session Load opens on the current character and allows browsing others. Title Load opens on the character with the latest save. Save mode is restricted to the current character, with a New Save action and explicit overwrite confirmation.
- **UI-010-D02.** Keep recognized unavailable slots visible with a reason when known. Use a placeholder for missing screenshots. Cancellation or preflight failure returns to the picker and retains the same selection when it remains valid. An absent or changed slot requires a fresh selection before loading.

See the [gameplay decision log](../../GAMEPLAY_DECISIONS.md#ui-010-interview-decisions).

## Existing Daggerfall Unity behavior

In the local DFU 1.1.1 snapshot, `Assets/Scripts/Game/UserInterfaceWindows/DaggerfallUnitySaveGameWindow.cs#UpdateSavesList` refreshes entries by mode, `#UpdateSelectedSaveInfo` reads metadata and screenshot for the selected slot, and `#SaveLoadEventHandler` dispatches the applicable flow. `DaggerfallLoadClassicGameWindow.cs` provides a separate classic path. CORE-013 limits this project's picker to its own native saves. Findings are from static inspection.

## Detailed rules and behaviors

1. Use SAVE-provided stable character, slot and generation identity. Use display names only as labels. Characters with the same name remain distinguishable. Sort each character's slots by SAVE's committed timestamp, newest first, with stable identity as a deterministic tie-breaker. The title selects the group containing the latest recognized timestamp. Keep missing dates clearly unknown and sort those entries after dated ones. Opening the picker or changing its selection cannot submit an operation.
2. Show the available slot name, character, timestamp, contextual location and screenshot as SAVE provides them. Use a placeholder when the screenshot is missing or unreadable. Distinguish unavailable payloads from cosmetic preview failure. For known unavailable slots, show the owner-provided reason and any supported remedy, and disable the action that cannot proceed. Metadata alone does not establish compatibility. SAVE and CORE preflight remain authoritative.
3. In Save mode, New Save requests a distinct slot through SAVE. Selecting an existing eligible slot and confirming overwrite targets the selected generation. If that target changes or disappears during confirmation, reject the request and refresh. Apply SAVE's write eligibility and naming rules. Report success after persistence, then refresh from the updated index. Write failure uses the owner recovery path.
4. In Load mode, capture the selected generation and submit through CORE-007/013. During an accepted request route required living-session discard confirmation and preflight through CORE. Successful replacement retires the old picker scope. Where cancellation or preflight failure leaves that scope valid, return to the picker, show the applicable outcome, and restore the same selection and focus if the selected generation still matches. If it changed or disappeared, clear the actionable selection and require the player to select again. After a failure that invalidates the old session, use CORE recovery.
5. Distinguish an empty list from an index error and keep Retry or Back reachable where applicable. A loading or writing operation may show a pending state and prevent duplicate or conflicting actions. Late metadata, preview and operation callbacks update only their matching scope and selection. A refresh cannot silently submit or retarget an action.

## Parameters, required data and configuration

No gameplay formulas apply. Required data includes mode, current character and session context, stable slot/generation and character IDs, available labels and metadata, SAVE timestamp, screenshot status, availability and reasons, and operation outcomes. SAVE defines metadata format, available preview fields, naming and slot constraints. The picker defines selection and presentation. None of the picker states grant eligibility.

## Inputs, outputs and events

Inputs include Open Save or Load, group and slot selection, New Save, overwrite response, Load, Back, index refresh, and owner outcomes. Outputs include rendered previews, reasons and selection state, targeted SAVE/CORE requests, pending feedback, and return or recovery routing. Dispatch through UI-002 and consume confirmation and handoff input under UI-001/005.

## Cross-system interactions and consistency

Reviewed against CORE-007 session coordination and discard confirmation, CORE-013 native-only preflight and restoration, CORE-018 stable quick-target rules, and UI-001/002/004/005 navigation, command identity, focus and confirmation. SAVE owns indexing, write targets, validation and persistence. Manual browsing across characters does not change the approved current-character quickload target. CORE-014 remains outside current scope.

## Edge cases and failure conditions

- Two characters can share a name. A removed, replaced or resorted slot cannot redirect a request to another row.
- Missing thumbnails use a placeholder. A corrupt or incompatible payload uses the owner's actual availability and recovery state.
- An empty current-character group allows browsing in Load, or New Save in eligible Save mode. An index failure receives an explicit status.
- Repeated button presses and late preview callbacks cannot trigger duplicate writes, change target or report success for a retired session.

## Save/load considerations

Picker selection, preview cache and pending UI state belong to the current view scope. Preserve focus and selection when returning from a child prompt or recoverable attempt under UI-001. Fresh entry uses the confirmed defaults. Durable slots and metadata are owned by SAVE.

## Technical constraints

Target Godot 4.7.2. Bind actionable rows and requests to stable owner identities. Keep metadata and screenshot presentation independent of preflight and persistence. Support the keyboard/controller focus and responsive layout requirements of UI-004. Exact widgets, preview loading strategy and owner APIs remain implementation choices.

## Acceptance criteria

1. Save and Load display native saves grouped by stable character identity, newest first. In-session and title entry use their respective default groups.
2. New Save creates a distinct slot through SAVE. Overwrite requires explicit confirmation, and a changed generation cannot receive that confirmation.
3. Recognized unavailable slots stay visible with known reasons. Missing imagery shows a placeholder and leaves compatible saves selectable.
4. Cancellation or recoverable preflight failure returns to the same valid selection. Changed or missing targets require fresh selection.
5. A pending request cannot repeat, retarget or report false success. Recovery after session invalidation follows CORE.
