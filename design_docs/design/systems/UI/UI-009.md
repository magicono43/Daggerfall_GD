# UI-009 — Pause options and configuration

**Approval status — Approved, finalized v1.** The user approved Draft v1 on 2026-11-16 with “I approve”. Updated 2026-11-16.

## Gameplay purpose and intended experience

Resume play, manage saves or adjust settings from the pause menu. Show players what they are editing, what will take effect now or later, and whether their changes were saved. Let them sample volume and UI size before committing.

## Confirmed requirements

- **UI-009-D01.** The pause menu offers Resume, Save, Load, Settings and Return to Title, with common volume controls directly accessible. Categorized settings are shared with the title menu. Hide session-only actions at title and explain visible restrictions in play.
- **UI-009-D02.** Preview audio volume and UI size reversibly before Apply. Resolution and fullscreen use the existing timed test. Bindings and gameplay settings activate through Apply at their declared boundaries.

See the [gameplay decision log](../../GAMEPLAY_DECISIONS.md#ui-009-interview-decisions).

## Existing Daggerfall Unity behavior

Static inspection of the local DFU 1.1.1 snapshot shows that `Assets/Scripts/Game/UserInterfaceWindows/DaggerfallPauseOptionsWindow.cs` wires Continue, Save, Load, Exit, controls, sound, music, detail, fullscreen and head bobbing in the pause window. Its `OnPop` saves changed settings. `DaggerfallControlsWindow.cs` has separate input rebinding and checks duplicate bindings before leaving the controls flow. `Game/DaggerfallUI.cs#ProcessMessages` routes to pause and configuration windows.

## Detailed rules and behaviors

1. Present Resume, Save, Load, Settings and Return to Title in the active pause context. Resume follows UI-001 and releases the pause menu's own requests. Save and Load open the eligible owner flows. Return to Title uses CORE-008 consent and teardown. Disable a visible restricted action with an owner-supplied explanation where available. The title settings entry uses the same setting definitions, validation and applicable preferences.
2. Expose sound and music volume directly on the pause menu, using the same staging and reversible preview behavior as the Audio page. Use a single settings draft for the visit across the quick controls and categorized pages. Navigating among pages preserves the draft and reflects edits made in either place. Apply and Cancel are reachable from the quick controls when edited.
3. Preview volume using the staged value in the active audio mix and preview UI size on the visible settings surface. Apply committed UI size to other views through their owner. Reflow the preview and matching hit regions together under UI-004. Preview lifetime follows the editing scope, including when a child dialog covers it. Cancel restores the prior effective values and discards unapplied edits. After Apply, resolve previews to each group's committed outcome. If an accepted group cannot be saved, retain its active values and expose Retry Save.
4. If the player leaves the editing scope via Resume, Back, Return to Game or another navigation path that would discard unapplied edits, offer Apply, Discard and Keep Editing where supported. Use existing owner gates when actions conflict. If Apply still needs confirmation or leaves unresolved rejection, keep the relevant settings or recovery surface available. Forced scope teardown clears previews without committing edits. CORE-008 governs the separate unsaved-game confirmation.
5. Show setting availability and activation timing before Apply, including the actual timing of an interdependent group. Distinguish staged, effective, accepted pending, rejected and accepted unsaved values. Show fallback or unsupported reasons and explicit partial success. Cancel discards only current unapplied edits. Retrying persistence does not reapply the setting or accelerate a deferred boundary.
6. Route resolution and fullscreen through CORE-006 test mode on Apply. Provide Keep Changes and Revert with a visible countdown. Revert after 15 real-time seconds unless explicitly confirmed, even during pause or focus loss. Test candidates remain unaccepted until confirmation. Unsuccessful safe reversion uses CORE recovery.
7. Rebinding captures input in the controls context under UI-002 and approved MOVE rules. Resolve same-context conflicts explicitly before Apply and preserve required navigation and device-loss recovery. Binding capture does not dispatch gameplay actions. Individual gameplay and device owners determine applicability, group boundaries and supported defaults.

## Parameters, required data and configuration

The display confirmation deadline is test start plus 15 real-time seconds under CORE-006. No new gameplay formula applies. Required data includes setting and group identities, categories, value constraints, requested/effective/staged/persisted values, activation boundaries, preview state, validation and failure reasons, and runtime capability. Individual owners define options, defaults, allowable ranges, supported fallbacks and activation timing. Audio and UI-size previews are scoped to the current edit.

## Inputs, outputs and events

Inputs include pause/title settings entry, edits, binding capture, Apply, Cancel, navigation, display test responses, timeout and Retry Save. Outputs include previews, validation, accepted and rejected group outcomes, visible pending and unsaved states, navigation or recovery. CORE-003/006 supply authoritative settings outcomes. Session actions use their owner routes.

## Cross-system interactions and consistency

Reviewed against CORE-003/006 for application and persistence, CORE-007/008 for session transitions and consent, CORE-016/018 for context and bindings, UI-001/002 for handoffs, UI-004 for scaling, UI-005 for confirmation, and MOVE for device policies. SAVE validates save/load entry. AV controls the audio mix and display backend. Preview changes are temporary presentation operations within the approved staged workflow. The display test continues under its own clock.

## Edge cases and failure conditions

- Settings opened from title and play show the same accepted preferences with restrictions appropriate to the context.
- Visiting the Audio page after editing quick volume shows the same draft. Cancel or forced closure clears uncommitted previews without undoing accepted groups.
- A UI size preview cannot make Apply, Cancel or navigation unreachable. Display test timeout remains effective without focus.
- A failed group reverts safely or uses recovery. A persistence failure shows that active changes still need saving. Closing the screen does not erase that status.
- Duplicate Apply or session navigation cannot repeat a test or silently commit a draft. Controller disconnect uses approved recovery without firing a binding or confirming a dialog.

## Save/load considerations

Settings are application preferences under CORE-003 and associated owner contracts. Active drafts, preview values and display tests are runtime state. A character load does not overwrite application preferences. Loading, leaving a session or restarting follows existing validation and readiness rules, with pending settings activated only at their declared boundary.

## Technical constraints

Target Godot 4.7.2. Provide one staged model per editing scope. Tie preview rollback to scope lifetime and apply grouped changes through validated owner operations. Preserve display confirmation independently of gameplay time. Exact screen layout, controls and backing APIs remain implementation choices.

## Acceptance criteria

1. Pause exposes the declared actions and direct sound/music volume. Title and pause use the same settings definitions, with only applicable actions visible or enabled.
2. Quick audio and Audio page edits stay synchronized. Volume and UI-size previews are reversible and do not persist before Apply.
3. Leaving a dirty editing scope handles the draft explicitly. Returning through child pages preserves it.
4. Apply and Cancel preserve the CORE-006 distinction between rejected, applied, pending and unsaved. Retry saves accepted values without reapplying them.
5. Display testing accepts only explicit Keep Changes and reverts on timeout under pause or focus loss.
6. Binding conflicts and device disconnect preserve required navigation. Save, Load and Return to Title follow owner checks.
