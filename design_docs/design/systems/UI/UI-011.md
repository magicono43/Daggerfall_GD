# UI-011 — Character creation navigation

**Approval status — Approved, finalized v1.** The user approved Draft v1 on 2026-11-16 with “I approve”. Updated 2026-11-16.

## Gameplay purpose and intended experience

Guide players through character creation one step at a time. Let them review the result and make the approved final edits before starting play. Give mods supported ways to customize the screens and creation flow.

## Confirmed requirements

- **UI-011-D01.** Use a clean DFU-style presentation with the current step title and no separate progress indicator. Make the character creation process moddable.
- **UI-011-D02.** In stock creation, follow the required linear sequence within the chosen branch before exposing Begin Game on the final summary.
- **UI-011-D03.** Preserve direct summary edits for name, face, attributes, skills and reflexes. Correct unfinished allocations before Begin Game can succeed.

See the [gameplay decision log](../../GAMEPLAY_DECISIONS.md#ui-011-interview-decisions).

## Existing Daggerfall Unity behavior

In the local DFU 1.1.1 snapshot, `Assets/Scripts/Game/UserInterfaceWindows/DaggerfallStartNewGameWizard.cs` uses ordered stages, branch-specific windows and close handlers to populate a character document. `SummaryWindow_OnClose` hands an accepted document to `StartNewGame`. `CreateCharSummary.cs#OkButton_OnMouseClick` checks for unallocated bonus points before finishing, and the summary exposes edits for name, face, attributes, skills and reflexes. These are static source findings.

## Detailed rules and behaviors

1. Stock creation presents the CHAR-001 sequence and its approved branches. Each presented step has a title and the applicable controls. Next advances only after that step's required choices pass their owner checks. Back returns along the active branch, preserving compatible choices and existing rolls. Substantive edits follow the applicable CHAR rules for dependent choices and rerolls. Merely navigating performs no roll or character grant.
2. Present the final summary only after traversing the required sequence. Show all creation choices and known starting effects under CHAR-001 and applicable disclosure rules. Expose direct editors only for name, face, attributes, skills and reflexes. Returning from an editor refreshes the same summary. Changing race, gender, class or biography from the summary requires Restart under CHAR-001. Summary Back follows the approved sequential path.
3. Show one Begin Game action on the summary. Block completion when requirements are unmet. Show an explanation on the affected section, including remaining allocation points where applicable, with correction through the allowed editor or existing owner flow. The final submission revalidates the completed draft.
4. Restart and exit discard the whole draft immediately under CHAR-001. Retire prior step state, generated values and outstanding callbacks. Restart opens the first step with a fresh draft. Exit returns through the owning navigation scope. Consent for replacing a living gameplay session remains governed separately by CORE-007.
5. Capture the validated character intent once and hand it to CORE-007. Show pending state while the request is admitted. A repeated action or late callback cannot start another character. CHAR-001 governs the three optional introductory clips, their order and bypass behavior. UI-008's startup-clip switch applies to the startup clip. CORE-011/012 own placement, initialization, opening popups and gameplay readiness.
6. Apply UI-003 targeted changes and whole-view replacement to supported creation windows. Use a documented mod extension path for creation steps and branches, labels, presentation, and supported choice content and rules. Validate modded routes before main-menu entry for reachable completion and exit, prerequisites, required owner data and supported action hooks. Modded flows can present a different sequence while meeting the applicable CHAR/CORE draft and submission contracts. Modded definitions follow DATA/MOD activation and compatibility policy.

## Parameters, required data and configuration

Required data includes the creation draft identity, current step and active branch, compatible choices and existing generated outcomes, validation and allocation results, summary data, mod contributions, and captured submission/request identity. No new formulas, roll limits or allocation values apply. CHAR owners define choices, calculations and disclosure. UI/MOD define supported presentation and flow extension points.

## Inputs, outputs and events

Inputs include character creation entry, choices, Back, Next, summary edits, Restart, exit, Begin Game, validation and CORE/AV outcomes. Outputs include updated draft state, current step or summary, actionable validation feedback, draft discard and scoped new-character submission. Only CORE publishes actual entry completion.

## Cross-system interactions and consistency

Reviewed against CHAR-001–010 for the stock sequence, retained choices, summary restrictions and discard, CORE-007/011/012 for submission and entry, DATA-003/008 for activation and choice definitions, and UI-001 through UI-005 for navigation, routing, customization, focus and prompts. UI-008 governs startup/death presentation. Introductory creation media follows CHAR-001 and cannot bypass entry prerequisites.

## Edge cases and failure conditions

- Revisiting a step or returning from a summary editor preserves eligible allocations and rolls. The active branch determines which steps remain required.
- Missing or invalid required selections block completion and identify the affected area. A modded route cannot bypass owner validation or make creation impossible to leave.
- Exit and Restart invalidate old callbacks without asking to discard the draft. Repeated Begin Game activation can submit only one request.
- Optional cinematic failure continues through the remaining approved sequence. A startup or entry failure follows the owning CORE flow.

## Save/load considerations

Unfinished creation drafts are runtime state and are discarded on exit or restart. CORE may retain identity-bound submission data for supported retry. Completed characters enter the normal SAVE contract. Loading does not recreate a draft or replay new-character grants.

## Technical constraints

Target Godot 4.7.2. Keep the draft and rule evaluation independent of view instances. Validate modded routes and definitions before activation. Use stable step, choice and request identities. Exact screen layout, extension schema and integration APIs remain implementation choices.

## Acceptance criteria

1. Stock steps show their current title, follow the selected branch in order and expose Begin Game only on the final summary.
2. Back and Next preserve compatible choices, allocations and rolls. No navigation action triggers a reroll by itself.
3. The summary directly edits only the five approved areas. Unfinished allocations block completion and identify where to correct them.
4. Restart or exit discards the draft immediately without confirmation. Old callbacks cannot repopulate it.
5. Mods can make targeted changes, replace supported creation screens and customize declared steps or branches. Invalid routes or missing required capabilities receive pre-menu validation feedback.
6. A valid submission hands off once. Presentation completion, skip or failure cannot report a playable entry before CORE is ready.
