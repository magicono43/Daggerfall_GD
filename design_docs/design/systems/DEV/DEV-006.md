# DEV-006 — Enemy spawn and AI console controls

**Approval status — Approved, finalized v1.** Updated 2026-11-18. See DEV-006-A01 in the [decision log](../../GAMEPLAY_DECISIONS.md).

## Purpose and intended experience

Let players and developers stage enemy encounters in a ready gameplay session, inspect a particular enemy, or temporarily stop enemy decisions while setting up a test. Test arenas can be assembled as needed using normal game systems. The feature adds built-in state-changing commands to [DEV-003](DEV-003.md).

## Confirmed behavior

1. Spawn one enemy from any registered enemy NPC archetype, including validated registrations from enabled mods. The command is available in any ready gameplay session. It uses the aimed point within short range and the archetype's normal placement rules. An obstructed or unsuitable placement gives a reason and leaves the scene unchanged.
2. Create the actor through [NPC-005](../NPC/NPC-005.md). The resulting actor participates in ordinary combat, loot and save behavior.
3. Provide explicit enemy AI on, off and status controls for the aimed enemy and for all enemies in the current session. Session-wide suppression also applies to enemies spawned while active. Overrides clear on session end or successful save load.
4. AI suppression stops autonomous enemy behavior. Enemies still take damage, can be knocked back and can die. [COMBAT-015](../COMBAT/COMBAT-015.md) governs interruption of unfinished enemy attacks and existing attack intervals. Independently released attacks retain their normal delivery.

See DEV-006-D01 through D04 in the [decision log](../../GAMEPLAY_DECISIONS.md).

## Approved targeting and override rules

- Resolve the spawn target by stable archetype ID and validate the aimed surface, clearance and current session before creating the actor. Publish one fully configured actor after construction succeeds. Show the archetype and resulting actor identity in the command result.
- Use independent per-actor and session-wide suppression. Either can suppress AI. Setting a scope to on clears suppression for that scope. Status shows effective AI availability and whether per-actor or session-wide suppression is active. Clearing command suppression leaves ordinary restrictions such as paralysis in effect.
- Reject an aimed AI command when there is no eligible live enemy in the current aim target. Re-enabling AI uses current targets and eligibility through the normal AI rules. Unfinished canceled attacks stay canceled.

## Parameters, data, inputs and outputs

Required inputs include command arguments, stable archetype ID and provider, current ready session identity, current player aim, placement validation and the aimed actor's stable identity for targeted AI control. Keep the session-wide flag and scoped actor suppression for the current session. Command results report spawn success, rejection or failure, or the requested AI status. The command adds no combat formulas. The exact short-range limit, command syntax and status wording remain technical decisions.

## Interactions, save/load and failure cases

- DEV-003 governs availability, argument errors and dispatch. DATA/MOD supplies the validated archetype registry. NPC and the location owner apply construction and placement rules. COMBAT governs damage, interruption, knockback and death. ITEM governs loot. SAVE determines the persistence of the normally spawned actor and its effects.
- Restore saved actors through normal SAVE rules. Debug AI flags are session data outside saves. A failed load that leaves the original session active retains that session's flags. A late command result cannot act on a replacement session.
- Unknown archetypes, missing required data, invalid placement and unavailable sessions fail visibly. Incomplete setup leaves no published actor. An eligible retry follows NPC-005 operation rules and cannot duplicate a settled actor. Physics and encounter effects use their normal owners.
- Target Godot 4.7.2. Use normal enemy construction and placement for ad hoc testing. A dedicated fixture editor and arena builder are outside this feature's scope.

## Acceptance criteria

1. A player can spawn one stock enemy and one registered mod enemy in a ready session. Each uses the normal archetype and placement path and behaves as an ordinary actor.
2. Invalid aim, insufficient clearance, unknown archetype and stale session requests report a reason and produce no enemy. Construction failure leaves no partially published actor.
3. Targeted suppression affects the selected enemy. Session-wide suppression affects current and subsequently spawned enemies. Status identifies overlapping suppression and clearing one scope preserves the other.
4. AI-suppressed enemies can take damage, be knocked back and die. Unfinished attacks are canceled according to COMBAT-015, released projectiles continue, and re-enabling AI allows fresh decisions.
5. An ordinary save can retain eligible spawned actors and their effects. A successfully loaded or newly started session has no inherited command AI suppression.

## Consistency review and outstanding questions

Reviewed on 2026-11-18 against DEV-003, NPC-005 and COMBAT-015. This feature extends the console's built-in list and follows established mutation, persistence and attack-interruption rules. Exact range, syntax and engine interfaces remain open.
