# DEV-010 — Location and terrain inspectors

**Approval status — Approved, finalized v1.** Updated 2026-11-18. See DEV-010-A01 in the [decision log](../../GAMEPLAY_DECISIONS.md).

## Purpose and intended experience

Help authors locate and inspect a settlement, interior or dungeon as assembled from its resolved content. Authors can identify placed objects and entrances, see their relationship to the surrounding layout and terrain, and investigate placement or connection problems.

## Confirmed behavior

1. Provide a searchable 3D preview of settlement exteriors, interiors and dungeons. Include nearby terrain when viewing an exterior.
2. Selecting a placed object or entrance shows its stable identity, source and transform. Show placement and connection warnings when available from the owning validators.
3. Keep inspection read-only. Provide optional preview overlays for block boundaries, entrances and collision. Persistent block and world authoring are reviewed under DEV-011 and DEV-012.

See DEV-010-D01 and D02 in the [decision log](../../GAMEPLAY_DECISIONS.md).

## Approved preview controls

- Provide an independent preview camera and a focus action for a selected object or entrance. Camera movement and overlay changes affect only the preview.
- Display the resolved layout and its available provenance. If a required dependency prevents preview, identify the affected content and reason. Label any partial preview and indicate which diagnostics could not be run.
- Initial dungeon previews use the resolved layout and inputs for the selected dungeon. Alternate seed exploration can be reviewed when an authoring workflow needs it.

## Required data, inputs, outputs and events

Inputs include search and selection, validated content context, stable location and placement references, preview navigation and overlay preferences. Required data includes source/provider provenance, resolved transforms and coordinate context, terrain and geometry, collision, entrances, bindings and available validation outcomes. Outputs include a read-only scene preview, selected placement details, overlay states and diagnostics. Exact event and API names remain technical design.

## Interactions, parameters and save/load

- [LOC-001](../LOC/LOC-001.md) supplies exterior placement and terrain shaping rules. LOC and WORLD supply the resolved layout, surrounding terrain and validation context. AV supplies the preview render path. Use owner data for overlays and warnings.
- [DEV-009](DEV-009.md) covers individual model inspection. [MOD-007](../MOD/MOD-007.md) covers content provenance. Previewing content preserves the active configuration and original files.
- No gameplay formulas or balance parameters apply. The terrain preview radius, coordinate display, camera defaults and optional overlay presentation remain technical details.
- Preview state is tool state. Inspection does not move a live character, activate a location in a gameplay session, advance the world or write character saves.

## Edge cases and technical constraints

Target Godot 4.7.2. Use the resolved layout and coordinate conventions for preview placement. Distinguish repeated instances of one block by placement identity. Show unknown provenance or unavailable diagnostics explicitly. Changing the selected location or content context retires stale preview requests and results. Keep rendering and inspection usable when optional decoration is absent under the applicable owner policy.

## Acceptance criteria

1. Search and open representative exterior, interior and dungeon previews. An exterior shows nearby terrain using the resolved layout and transforms.
2. Selecting an object or entrance identifies the placement, source and transform. Validation warnings link to the affected placement or connection when that information is available.
3. Block, entrance and collision overlays can be shown or hidden independently. Focusing a selection moves only the preview camera. Inspection leaves source files, active player position and save state intact.
4. A required missing dependency produces an actionable diagnostic. A partial preview is visibly identified, and an unavailable validation result cannot appear as a successful check.

## Consistency review and outstanding questions

Reviewed on 2026-11-18 against LOC-001, DEV-009 and MOD-007. The inspector uses layout and provenance results from their owners and provides preview controls within its own scope. Search UI, terrain extent and render integration remain open.
